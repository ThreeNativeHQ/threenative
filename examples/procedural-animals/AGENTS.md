# AGENTS.md — procedural animals example

Read the root and `examples/AGENTS.md` first. This owns one baked wolf, high/crowd geometry, editable base DQS material and motion source. Fur/fins/eyes/full species catalogue are outside this consumer.

Generation runs only in `scripts/bake-assets.ts`. The portable entry loads the normal asset manifest through `ctx.assets.resolve`; corruption rejects and never regenerates an animal. Render and donor motion source under `src/render/` remain editable game code; preserve the pinned MIT notice and report source hashes when qualifying an edited consumer.

Rapier's completed fixed step is the sole root writer. `afterPhysics` computes accepted displacement velocity and hands that state to `follow`; requested controller velocity is not accepted velocity. The first adapter rejects a parent whose world transform is not identity. The game measures each bake's maximum bind-vertex distance from the rig origin once and uses the shipped sphere primitive for conservative horizontal clearance against this tall wall. Both tiers and lifecycle generations share that rule. This is not volumetric containment of several grounded paws. The explicit `visualOriginOffset` is minus the measured radius; the actor reports it. The physical sphere and controller clearance can leave a small slope gap, which is measured rather than claimed as exact foot contact. Ground heights come from physics rays using the level-only collision mask. Teleport goes through the body first, then resets animal history. Pause freezes pose evaluation; disposal removes the actor and releases its geometry/material/pose texture.

DQS includes the donor affine scale pre-pass, hemisphere alignment, real/dual normalization, position translation and normal rotation; the shadow path uses that same deformed position. Animated bounds are measured from the current pose packet and bake, never an unbounded sphere or disabled frustum culling.

Two installed hardware browser attempts remain failed and preserved: the first final capture/triviality failure and the second missing entity-visibility observation. The second attempt has actual nonblank deformation/shadow PNGs and nine GPU cases within tolerance, but its descriptive scenario subject requested no wolf. Correctness fixtures now name `wolf-0`. Full browser qualification, Linux native and performance remain open; supporting pixels/numeric/draw observations do not pass the platform AC.

Qualification uses `game.ts` on browser and desktop. KeyP explicitly arms the diagnostic after the runner baseline; KeyN releases the held 2/4.5/11/24.5 second capture milestones and KeyF selects the outside view. Captures hold the pose and camera during screenshot latency. Camera placement uses the measured bind center after completed physics, follow and pose, including teleport; root-error reporting retains the maximum across all completed steps. The close correctness camera and course-visible outside camera belong to `src/render/`; performance modes keep the full-crowd camera. Browser playtests use `--live-clock`; the ordinary desktop bundle/mailbox uses its reported fixed-step clock. Native production profiling requests live clock through its existing instrumentation prelude rather than a host flag. The asynchronous GPU probe compares immutable pose snapshots with the independent CPU oracle. Its invisible diagnostic Mesh uses `frustumCulled: false` solely to establish normal Three attribute ownership; actual wolf meshes retain measured animated bounds and frustum culling. It stays hidden during startup compilation, exposes no warmup compute, and waits for a completed render with `renderer.compiling === false` before dispatch. This scene does not issue later explicit asynchronous compilation of the probe.

`crowd.html`, `high.html` and `baseline.html` use matching portable entries for paired performance runs. Those modes never create the diagnostic probe. Each records actual visible wolf submissions before measurements; a visible wolf omitted from the renderer fails. The baseline shares the collision course and lighting. The separate `lifecycle.html`/`lifecycle-game.ts` entry starts on KeyL after runner baseline and drives fifty distinct 32-wolf generations on one persistent renderer. It validates actual main/shadow draws, scoped live WebGPU buffer/texture identities and exact buffer bytes, Three memory, bodies/entities/listeners/callbacks/actions, and returns to the stabilized shared baseline after queue completion. The observer-install snapshot excludes explicitly pre-existing device resources; `firstReadyDraw` describes a post-ready observation, not the first-ever frame. A named resolution-scale/pixel-ratio override stabilizes this resource test and remains reported. All five entries are included in Vite. Fifty real GPU lifecycle cycles and the original paired CPU/GPU frame budgets remain unverified.

All five authored HTML entries give the canvas `width: 100%` and `height: 100%`, independently of its drawing buffer dimensions, matching the generated minimal template. Otherwise adaptive resolution can shrink CSS layout as well as the physical buffer. The focused CPU regression loads inert HTML with GPU disabled and changes the physical canvas dimensions; it does not qualify game pixels.

Desktop uses `animals.native.playtest.json` and `frustum.native.playtest.json` with the same baked assets and `src/game.ts`. Original motion steps, numerical thresholds and actual submission predicates remain intact. Existing labeled native PNG/tone capture plus the public capture guard, recorded decoded-PNG dimensions and public frame-budget surface measurements and independent image review establish actual deformation/shadow pixels. Native target diagnostics record the unavailable CDP network observer; no empty network series counts as a passing observation. These fixtures are prepared and schema-validated only until an actual allocated native run.

Native captures contain drawing-buffer pixels, which adaptive resolution can make smaller than the requested host window. Record their decoded dimensions and existing `TN_FRAME_BUDGET` surface data; do not mistake a 1,280×720 window request for a required PNG size or pin correctness rendering solely to match one.
