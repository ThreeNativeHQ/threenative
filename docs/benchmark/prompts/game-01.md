# Game 01 — Abyss interaction prompt

Build a small, polished underwater game called **Abyss**.

The player controls a warm light in a dark ocean. Use the light to attract glowing
collectibles, collect at least three of them, and avoid hostile shapes that approach
the player. Include a clear start state, a playable state, a score, a health or danger
indicator, and a game-over or restart path. Make the scene feel intentional: use a
strong palette, readable hierarchy, motion, and feedback for the primary interaction.

Requirements:

- Use the project dependencies and entry point already present in the directory.
- Keep rendering and game code readable and editable by another developer.
- Support mouse or touch and Arrow/WASD keyboard movement.
- Support a held action key or pointer action that changes the game state.
- Keep the first meaningful interaction reachable within 30 seconds.
- Add a browser playtest that boots the game, exercises movement and the primary action,
  and asserts that the score changes.
- Run the project build and playtest before handing it back.

The acceptance contract is identical in both benchmark arms. Do not mention which arm
provided the starter files, and do not add arm names to visible UI or artifact paths.
