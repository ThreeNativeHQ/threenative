# PRD-212 Phase 2 — the Android clean room proves the stranger's path (2026-08-23)

Lane: this repository's checkout, `main` at `9a116af3`. **No device, no publish, no tag.** The
clean-room gate runs entirely on loopback and is re-runnable on any machine with no network.

## Why the existing Android tests could not have caught bug 6

Every other Android test in `packages/runtime-native/tests/distribution.test.mjs` runs inside the
workspace, where `CMakeLists.txt` and a staged `third_party/sdl3-android/SDL3-3.2.8.aar` are simply
present. `packageAndroid` therefore takes the **source** path
(`package-android.mjs:552-554`) and the prebuilt path is never exercised. A stranger has neither
file, which is the only arrangement in which the 404 could ever be seen.

The new gate installs the packed tarball into a directory with no workspace and no engine checkout,
and drives the packager from *there*. It asserts the detection first, so the test cannot silently
degrade into proving the workspace path again:

```js
assert.equal(existsSync(join(installed, 'CMakeLists.txt')), false);
assert.equal(existsSync(join(installed, 'third_party/sdl3-android/SDL3-3.2.8.aar')), false);
```

## Red control observed: without the manifest hook, the stranger's build 404s

The first run of the clean-room gate, before it was pointed at the fixture manifest, reproduced
bug 6 exactly — from an installed tarball, with no engine checkout:

```
This install has no runtime source checkout at
/tmp/threenative-android-cleanroom-JlCayA/consumer/node_modules/@threenative/runtime-native,
so it tried to download prebuilt Android artifacts from a GitHub release.

Caused by: Error: Android prebuilt 'android-x86_64-v8-snapshot' expected from
'https://github.com/ThreeNativeHQ/threenative/releases/download/runtime-native-v0.3.0/prebuilt-lock.json':
Prebuilt release manifest fetch failed ... HTTP 404.
```

That is the live defect, not a simulation of it: the release genuinely does not exist. Setting
`THREENATIVE_PREBUILT_MANIFEST` to the fixture lock turns the same code path green, which is what
makes this an always-runnable regression gate rather than a test that waits on PRD-078.

## Negative controls

`the clean-room Android build fails loudly on a corrupt fixture manifest` pins three refusals, each
asserting the output root was **not** created:

| Mutation | Refusal |
| --- | --- |
| tamper one artifact's `sha256` | `Checksum verification failed ... android-arm64-v8a-runtime-v8` |
| delete `android-sdl3-aar` from the manifest | `No prebuilt release asset ... android-sdl3-aar` |
| point at an absent manifest | `No prebuilt release manifest exists` — and no network fetch |

The env hook redirects the lookup; it does not relax it.

## One honesty defect found and fixed while wiring this

`prepareAndroidPrebuilts` computed its `expectedSource` as
`options.manifestPath ?? options.manifestUrl ?? releaseManifestUrl(...)`, but
`downloadReleaseArtifact` prefers `THREENATIVE_PREBUILT_MANIFEST` over both. A failure while using
the env hook therefore reported the release URL — sending a reader to a 404 that had nothing to do
with their failure. `expectedSource` now consults the env variable in the same order the download
does.

## Cmake and the NDK are masked, and that is the design

The prebuilt path exists so a stranger compiles no C++. The gate masks Gradle through the packager's
existing `options.spawnSync` seam and asserts it was invoked with `assembleDebug`, after checking
that every artifact the fixture manifest named landed at the path the Gradle build reads. What is
proven is the stranger's path up to and including the build invocation, offline, on any machine.

**Not proven here:** that Gradle then produces a runnable APK from those artifacts. That needs an
SDK and JDK, and the fixture payloads are stand-ins rather than real `.so` files. Recorded as open.

## Hatch documented

`packages/runtime-native/README.md` gains a "Where the native binaries come from" section covering
both variables. `THREENATIVE_RUNTIME_SOURCE` is documented as requiring a **full engine checkout** —
it cannot be pointed at an installed copy, because the packager only takes the source path when it
finds both `CMakeLists.txt` and the staged SDL3 AAR, and a published tarball ships neither. The
section says plainly that it is not a way around a failing download.
