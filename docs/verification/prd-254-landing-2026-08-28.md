## The three pre-existing test failures, and what happened to them

They were present on the convergence branch before any lane in this PRD merged
(`git diff 85ef5a81 <merge> -- packages/runtime-native/` was empty each time).

1. **`tests/device-preflight.test.mjs` — real defect, fixed.** The suite asserts
   every lane that installs an APK calls `suppressPlayProtectOnAdbInstalls`
   first. Only `device-physics-stability.mjs` did — and its own comment claimed
   "as every other install lane does", which was false when written. The other
   five installed straight into a modal verifier dialog that eats injected
   touches.
   - Red observed: `AssertionError: measure-android-js-engine.mjs installs an APK without calling suppressPlayProtectOnAdbInstalls first`
   - Green observed after `fb402c9a`: `Tests 25 passed (25)`
   - Negative control observed: deleting the call from `qualify-physical-mobile.mjs`
     reproduces the same assertion naming that script — `1 failed | 24 passed`.
   - **Statically verified only.** No Android device was attached, so no claim is
     made that a real install now runs dialog-free.

2 & 3. **`tests/timestamp-query.test.mjs` ×2 — environmental, not a code defect.**
   They fail closed because the C++ `threenative-timestamp-query-test` binary is
   not built in a fresh worktree; `build/` is gitignored. The binary exists in the
   primary checkout. This is the suite behaving as designed — "an unbuilt
   executable is unexecuted, and says so" — not a regression from any lane.
