Date: 2026-08-28

Status: implementation complete in this lane. The source PRD remains unchanged at

## What shipped

- `GPUSceneBVH` packs selected visible meshes into world-space positions, indices, normals, and
  the serialized `three-mesh-bvh` node layout exposed as named TSL storage nodes.
- The core entry point exposes the upstream `bvhIntersectFirstHit` and `rayStruct` directly; the
  example owns the WGSL adapter and the visible contact-occlusion material in `src/render/`.
- Stable storage-node identities survive `rebuild()`. `GPUSceneBVH` implements `IComputeDriven`,
  releases all four storage buffers on detach, and is registered through `ctx.add`.
- The picking example exercises indexed grouped geometry, transformed meshes, and an
  `InstancedMesh`; its playtest asserts a changed rendered contact effect after rebuild.

## Cost and boundary

The public capability documentation records that `rebuild()` performs an explicit CPU flatten and
SAH build proportional to selected triangles. In the 72-triangle example, the observed build
measurement was approximately `1.3 ms`. `process()` is intentionally a no-op, so the package adds
no per-frame dispatch; the game-owned TSL kernel pays for each shader ray, and this example invokes
it per contact-floor fragment.

`ScenePicker` and `GPUSceneBVH` remain separate. `ScenePicker` owns object-local CPU BVHs and
camera/pointer ray semantics; `GPUSceneBVH` owns one predicate-selected, world-space storage
snapshot whose lifetime follows the renderer. Sharing the trees would couple CPU picking to GPU
buffer replacement and release without removing either representation.
