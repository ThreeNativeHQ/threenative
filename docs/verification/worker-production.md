## Clean-install game proof

Sandbox:
`/home/joao/projects/threenative/sandboxes/feature-mining-workers-20260829/prd250-worker-rule`.
It was generated by `pnpm sandbox`, installed only packed tarballs, and reported zero readable
framework-source lines.

The game starts a classic Blob worker that performs 30,000,000 deterministic integer operations.
The amber beacon becomes green and `outcome` changes from `playing` to `won` only when the worker
returns checksum `849418565` and the main loop observed at least one frame while the result was
pending.

text spliced inside the JSON because the marker used multiple stream insertions; commit
`a0e46ae0` composes the marker first and its rebuilt sandbox rerun retained the complete line.

## Negative controls

- Before the rollback selector implementation, the focused test constructed a worker while
  rollback was active: 1 of 12 tests failed because no named refusal occurred.
- With `THREENATIVE_NATIVE_WORKER_ROLLBACK=1`, the packed desktop acceptance command exited nonzero
  and retained `TN_NATIVE_WORKER_ROLLBACK_ACTIVE`. The selector intentionally refuses acceptance;
  it does not resurrect the incorrect inline executor.
- Changing the clean sandbox's expected checksum from `849418565` to `849418564` produced
  `outcome: "failed"`, exit 1 and overall `pass: false`; restoring it returned the web scenario to
  green.
- Before atomic marker emission, the external desktop log observed
  `[Worker TN_NATIVE_WORKER_CREATED:{"id":11,"engine":"] Thread started` followed by `V8"}`.
  The focused marker contract was red, then 19 focused tests and the rebuilt external executable
  were green.
