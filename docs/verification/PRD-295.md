# PRD-295 — Fab Unreal assets become runtime-ready ThreeNative GLBs

Run 2026-08-30/31 on this machine (Linux, NVIDIA Turing, WebGPU). Every command below was
executed; where something was not run, this file says so.

## What shipped

`threenative-asset-mcp` **0.6.0** (published; `npm view threenative-asset-mcp version` → `0.6.0`),
adding three tools to the live surface (32 → 35):

| Tool | Does |
| --- | --- |
| `asset_import_unreal` | Converts a local `.uasset` directory into source GLBs |
| `fab_import_asset` | Verifies entitlement, downloads via FabCLI, then the same conversion |
| `fab_list_owned` | Lists what the signed-in Fab account already owns |

Plus `threenative-asset-mcp import <url\|dir> --out <dir>` over the same handlers.

Engine pin moved `0.4.0` → `0.6.0` in `packages/core/package.json` and `packages/core/mcp/servers.mjs`
**after** the publish, per the PRD's release order.

## Owner decisions that changed the PRD

Both were requested during the run and are deliberate departures, recorded here rather than
silently absorbed:

1. **The external tools auto-install.** The PRD required resolve-or-fail so that using FabCLI's
   unofficial API stayed an explicit act. An agent that hits "umodel not found" has no way
   forward, so umodel and FabCLI now install themselves on first use.
   `THREENATIVE_TOOLCHAIN_AUTOINSTALL=0` restores the PRD's behaviour. Authentication is still
   never automated.
2. **A licence gate the PRD did not specify.** Only Fab Standard (Personal/Professional) and CC-BY
   are imported. Unreal-Engine-only and legacy entitlements are refused by name, and a licence that
   cannot be read is refused too — unknown fails closed. The check runs on the anonymous public
   listing *before* any download, so the gate never depends on the authenticated path it guards.

### Defects found and fixed, each of which produced a plausible-looking wrong result

- **Interleaved vertex layout.** glTF-Transform interleaves by default; ThreeNative's native asset
  preflight rejects an interleaved buffer view (`createRenderPipeline` fails on every mesh using
  one). The GLBs rendered fine in a browser and could not be packaged for desktop at all. The
  writer now pins `VertexLayout.SEPARATE`, and `validateGlb` fails closed using the engine's own
  definition — more than one attribute semantic per view, not the mere presence of a byte stride.
- **All-zero tangents.** UE Viewer writes a TANGENT accessor whose every element is `(0,0,0,1)`
  (5769/5769 on the fern). glTF requires unit length, and a renderer handed a zero tangent produces
  NaN under any normal map. Dropped, so the runtime derives the frame from UVs.
- **Masks bound as base colour.** umodel resolves a packed mask into its `Diffuse` slot because
  that is where the diffuse chain begins. Binding it turned the cave magenta. Measured separation
  on this pack: real albedo 0.09–0.13 saturation / 0.97–1.00 channel correlation; masks 0.78–0.84 /
  0.02–0.16. `classifyAlbedo` refuses the latter and writes them to `textures/` as sidecars so a
  game can rebuild the surface itself.
- **Licence lost on copy.** The entitlement now rides in the glTF `asset.copyright`, which is where
  ThreeNative's asset health check looks. Before this the models reported `license: unknown` in a
  game that had just verified them.
- **stdout truncation.** The stderr-fallback diagnosis clipped *all* FabCLI output to 4096 bytes; a
  real library is ~28 KB and came back "did not return JSON".

## The cave scene

`sandbox/soul-cave` builds the reference image's lighting from the imported pack.

The pack ships no rock albedo, so `src/render/rockMaterial.ts` rebuilds the surface as a TSL node
material from the mask the importer refused plus the real normal map, sampled at two scales so a
tiled floor does not read as wallpaper. The room itself is built rather than borrowed: the pack's
merged rock masses are 70 m blocks meant to be seen from outside, and standing inside one left
nothing to occlude the sun.

Three more silent-flat-image bugs, all in game code:

- `renderer.shadowMap.enabled` was never set, so no shadow map existed, so the godrays stage
  refused — and took the whole chain with it. `ctx.renderer.raw` is the three renderer;
  `ctx.renderer` is the framework wrapper and has no `shadowMap`.
- The roof's opening plane was `BackSide` after being rotated face-down: invisible from inside.
- The walls overshot the roof, so the hole showed wall instead of sky.

```
TN_RENDER_CHAIN: ambientOcclusion, ssgi, godRays, ssr, sharpen, bloom, vignette — 0 dropped
steady-state render p50 2.9 ms, p95 7.0 ms; 82 draw calls, 366,731 triangles
scenario performance gate maxFrameMsP95 33 — pass
```

Frame-time p95 reads worse than render cost because the private Xvfb throttles present; render
p50/p95 is the honest number on this lane.

**Not matched to the reference:** the reference has far more columns and higher-frequency rock
detail than a reconstructed-from-mask surface reaches. Closing that needs authored albedo, which
the pack does not contain.
