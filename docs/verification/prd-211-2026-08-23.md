## The stale claim

`asset-preflight.mjs` refused every WebP texture for Android with the reason "the android runtime
is built without libwebp". That sentence had been false since `62fac4d5` added `webp-source` to
`androidDeps`: `CMakeLists.txt:657-696` builds libwebp from source under `MYSTRAL_HAS_WEBP`, and
the device logs `[Mystral] WebP format support: YES`.

`tests/android-webp-provisioning.test.mjs` already named asset-preflight as leg 3 of a three-leg
sync triangle and pinned only legs 1 and 2. So the build changed and the claim about the build did
not, which is the whole disease: a hardcoded capability goes stale the moment the build moves under
it, and nothing can notice.

## Derivation table

`deriveAndroidWebpSupport(runtimeSource)` mirrors the ANDROID branch of the libwebp block —
`file(GLOB ${THIRD_PARTY_DIR}/webp-source/libwebp-*)`, take the first candidate with a
`CMakeLists.txt` and **no** `lib/`.

| runtimeSource | supported | reason |
| --- | --- | --- |
| checkout + `third_party/webp-source/libwebp-1.5.0/CMakeLists.txt` | **true** | names the provisioned tree and `MYSTRAL_HAS_WEBP` |
| checkout, `third_party/webp-source` absent | false | names `node scripts/download-deps.mjs --only webp-source` |
| checkout + `libwebp-1.5.0/lib/` present | false | a prebuilt drop in the source destination builds nothing — CMake's `NOT EXISTS <cand>/lib` |
| no `CMakeLists.txt` (published install) | false | a prebuilt Android release does not declare which decoders it was built with |

The last row is fail-closed and honest rather than derived: the prebuilt lock carries no capability
declaration to read. `install-prebuilt.mjs`'s manifest has no field for it, so the packager cannot
know, and refusing while saying exactly that beats guessing. If PRD-212's release work adds a
capability field to the manifest, this row becomes derivable and should be.

`findAndroidAssetProblems(directory)` with no capabilities argument uses `NO_DECODERS`, so a caller
that derives nothing gets the most restrictive runtime, not the most permissive one — pinned by
`a caller that derives nothing gets the most restrictive runtime, not the most permissive`.

## The iOS exclusion stays true

`CMakeLists.txt:697` excludes IOS from the prebuilt branch and the source branch is ANDROID-only,
so iOS genuinely cannot decode WebP. `the iOS exclusion stays honest: no libwebp is built for IOS`
pins that, so correcting the Android claim cannot quietly make the iOS one wrong the other way.
