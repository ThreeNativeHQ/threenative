## Notes

**`pnpm test` cannot complete in a worktree without a native build.**
`packages/runtime-native` fails six *"executable is not built"* assertions and aborts the recursive
run before the root vitest project, which is why the root suite is reported from a direct
`pnpm exec vitest run`.

**Nine dead documentation links failed `check:docs`, the suite's first phase — and they exist only
in local, unpushed `main` commits.** `docs/audits/` and `docs/PRDs/alpha-readiness/` are both still
present on `origin/main`; they were removed by `8d680023` and `ada4c10b`, which have not been
pushed, and the index rows and cross-references pointing at them were left behind. This round's
first branch carried a repair for them; on rebasing onto `origin/main` the repair became wrong —
it removes links to files that exist there — and was dropped. **The dead links will arrive on
`origin/main` the moment those two commits are pushed**, and whoever pushes them owns the repair.
Recorded here so the next lane that meets a red `check:docs` knows where it came from.

**`scripts/alpha-bar.ts` names `docs/PRDs/alpha-readiness/README.md` as its batch README.** That
file is deleted in the same unpushed commits, so `pnpm alpha:bar` will read a missing file once
they land. Found while investigating the links; not fixed here.

**`pnpm round:next` was stale again, and in the same direction as round 9 recorded.** It printed
`close round 12` against `docs/verification/round-12-close-2026-08-22.md`, a round already closed
on disk. The resume command pointed at an action that was already done, for the second time in the
loop's history. Not fixed here; recorded so round 14 does not follow it.

**The instrument told the truth about a fixture on its first real run.** `fps-friction`'s scenario
was first given `scene.minVisibleLights: 1` and failed with `{observed: 0, total: 0}`. The fixture
mounts no lights and its geometry is `MeshBasicMaterial`, so the bound asserted something that game
never intended. The bound was dropped, not the fixture changed. `litMaterialsAreLit` passing at
`{litMaterials: 0, visibleLights: 0}` is the correct reading of the same scene.

**Nothing in this repository walked, so the round built the walker and it immediately paid.**
`AnimationPlayer` had two live callers and neither covered ground, so `maxFootSlide` had unit proof
and no game behind it. `examples/fps-friction` now carries a patroller on a looping clip, and its
scenario found a defect in the bound itself: `maxFootSlide` read the stride report's `rate`
unconditionally, but that is the rate the player *measured* — an overridden clip keeps its authored
rate. An overridden run therefore scored **zero slide**, vacuously satisfying the one bound written
to catch it, and every unit test agreed because they were written against the same wrong reading.

That is the round's most useful result. A unit test written by whoever wrote the code tests the
reading they had in mind; the scenario tested the game. Fixed as `appliedStrideRate`, with the
control reporting `footSlide: 0.25` where it had reported `0`.
