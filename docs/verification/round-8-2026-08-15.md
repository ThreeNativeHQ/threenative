## Notes

**The same source on the original proof `33c3acb0`, kept for comparison.** Archive
`physics-puzzle-2026-08-15-7` (framework) scored 0/2 scenarios and 6/12 rows; archive
`physics-puzzle-2026-08-15-6` (vanilla) scored 0/2 and 8/12. Those two archives are the builds as
they were sealed; the `-8` and `-9` archives above are the same source re-sealed against the
repaired proof. They are recorded outside the Arms table because a round has one Arms table and
this round's arms are the ones scored on the instrument that works.

**Recorded deviation: one arm saw the other's process line.** While both arms were building
concurrently, the vanilla builder ran `pgrep -af vite` to free a stuck port and the output printed
the framework arm's full command line, including a `probe.playtest.json` that arm had written with
a heredoc. The builder reported this unprompted, supplied the raw text on request, and corrected
its own earlier description of it from two resource paths to five.

Adjudicated as a deviation rather than a contamination, and the owner accepted that call:

- The leaked file is that arm's own run-time debugging probe, not a sealed proof. Compared
  directly, it shares no assertion, no step label and no route with either sealed scenario.
- Every vanilla design decision predates it, with named artifacts: `mission: won` with
  `player|goal|trigger` contacts, `replayHashA == replayHashB == 3214079977`, `ghostPasses: 2`.
- Zero edits under `src/` after it appeared.

The firewall attestation rows above are unaffected, since none of them is the rule that was
touched. Future rounds run the arms **sequentially**, and builders are now told not to enumerate
the machine — recorded in `.agents/skills/self-improve/SKILL.md`.

**Second deviation: neither builder could load `build-on-sandbox`.** The skill lives inside this
repository, which builders are forbidden to read, so both proceeded on the lead's prompt and the
sandbox `AGENTS.md`. The firewall held only because the prompt restated it. Also now recorded in
the skill.

**Why the functional column is void.** The sealed replay proof required
`state.replayPhase` to equal `"done"` and `state.replayMatch` to equal the string `"match"`, and
the brief publishes neither value. The vanilla arm produced `"complete"` and boolean `true` from a
correct replay whose two runs hashed identical, and lost both rows to the guess. That is
PRD-113's exact subject, evidenced in
`docs/verification/prd-113-sealed-proof-still-tests-naming-2026-08-15.md` and repaired in
`e67a0d2d`. A functional column scored on an instrument that measures vocabulary is not a parity
verdict, so it is recorded `unmeasured` rather than as a framework loss.

The cost column does not depend on that instrument and stands: **the framework arm cost 210 more
authored lines than plain Three.js for the same brief.** Round 7 also showed a cost loss, but
round 7 was void, so this is the first of a possible two. If round 9 repeats it on a working
instrument, `CHARTER.md`'s kill-switch condition is met and the correct response is to say so.

**Machine contention shaped this round.** Three unrelated agent workloads ran on this host
throughout — a jest suite at ten workers, a `fox-native` dev server holding port 4173, and a peer
session in the same tree. It cost the visual column, hung the golden-path gate twice, and is the
direct reason the arms ran concurrently in the first place.
