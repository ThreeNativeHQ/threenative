here: the shipped gate passes in this repo's own template run today, so the navigation failure is

brittle assertions are a real defect and go in round 10 as their own change, with the question they

script.

## Notes

**Kill switch — resolved by the owner, 2026-08-15: the cost column is authored lines.** The stop
rule fires when the vanilla arm wins on cost across every genre for two consecutive rounds. Under
the *final* measure — what the user ends up owning — that had happened: round 8 by 210 lines and
round 9 by 162. Under the *authored* measure — what the agent had to write to reach the game — the
framework won both, by 290 and then 379, a widening margin. Round 8 declined to choose and called
it a charter question; it could not be declined twice, because the same ambiguity decided whether
a documented stop condition had been met.

The owner chose authored lines. The reasoning of record: the framework's promise is that you write
less to get there, and surviving template lines are generated source the user owns and can delete.
**So the kill switch is not armed**, the framework wins the cost column in rounds 8 and 9, and
round 10 reads this column the same way. The final-lines number stays in the Arms table because it
is true and answers a different question — what the user ends up carrying — but it is not the
verdict.

That decision has a consequence this round already acts on: if surviving template lines are the
user's to delete, a template that ships lines every real game deletes on contact is spending the
user's budget for them. Gap 3 is disposed on exactly that reading.

**Arms ran sequentially, per round 8's recorded deviation.** No process-line leak occurred. The
lead, not a builder, killed the stray servers — builders were forbidden to enumerate the machine
and both confirmed they did not.

**`build-on-sandbox` was inlined into both builder prompts**, because the skill lives in this
repository and builders may not read it. Round 8's builders both reported it missing; this round's
did not, because the prompt carried its method and its rules verbatim.

**Machine load at round start: 3.92 / 9.64 / 10.40, and 5.09 at capture time.** Frame timings swing
under concurrent load, and round 8 showed the functional column depends on render speed. The visual
column is the round's focus and reads from still frames, which this does not distort. The
functional column's one-row margin is read against this number and is called thin for that reason
as well as for the favicon.

**The blind judge saw two frames per arm this round, not one.** Round 8's critic recorded its own
limit — one still per sample, so playability rested on HUD readouts. Two frames per arm, an
opening and a later one from the same sealed scenario, is a direct response to that. This round's
critic still records the same limit for playability, correctly, and its visual scores are the ones
the column uses.

**`pnpm round:next` is reading stale state.** At the start of this round it printed
`pnpm sweep:proof docs/benchmark/sweeps/physics-puzzle-2026-08-15-9` — an archive round 8 already
records as not re-runnable, because PRD-113 moved the physics-puzzle brief hash and `sweep:proof`
refuses the mismatch. The resume command points at an action that cannot succeed. Not fixed this
round; recorded so round 10 does not follow it.
