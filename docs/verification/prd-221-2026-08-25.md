# PRD-221 Phase 0 — Android V8 16 KB decision memo

**Date:** 2026-08-25
**Decision:** **Path A — rebuild `v8-android-buildscripts` at HEAD with 16 KB ELF linker flags.**

## Current facts

The Android default is V8 (`-PthreenativeJsEngine=v8`); QuickJS is the documented rollback.
The repository's supported dependency flow currently downloads Kudo's `v8-android-jit` prebuilt,
which is 4 KB-aligned. The Kudo repository has no newer release carrying a 16 KB proof: its latest
published npm package is `11.1000.4`, and the repository's `main` still describes Android builds as
using NDK r23c. The current artifact therefore cannot be claimed as 16 KB-clean or used for a
Google Play submission that promises 16 KB support.

## Options

| Path | Effort estimate | Risk | Maintenance / licence |
| --- | --- | --- | --- |
| **A — build Kudo at HEAD** | 4–8 hours for a first arm64 + x86_64 build; follow-up work if the old patchset does not apply | High toolchain and V8 ABI risk; requires the existing V8 patchset plus NDK/page-size verification | `packages/runtime-native` owns the pinned source revision, patches, and NDK/toolchain refresh. Kudo's build scripts are BSD-2-Clause; V8 is BSD-style. |
| B — adopt another Android V8 distribution | 1–2 days after a candidate exists; discovery is unbounded | No maintained candidate with a compatible `libv8android.so`, snapshots, JIT, and 16 KB proof was found; ABI and licence provenance could differ | The runtime-native owner would still own ABI/snapshot updates. A candidate's licence and redistribution terms must be checked before adoption. |
| C — switch Android back to QuickJS | About 1 hour | Closes the V8 library issue by removing V8, but regresses the measured Android script performance and leaves the V8 default unresolved | No new dependency. The owner would need to explicitly own QuickJS as the interim default; it is not the current product decision and is not a V8 fix. |

## Recommendation and store claim

Path A is the only option that preserves the current V8 default and can produce the required
artifact through a source build. The attempt is intentionally limited to the existing Kudo source
and its Android patchset; no renderer or JavaScript-semantics change is in scope. If it fails, the
PRD will be filed under a concrete `BLOCKED/` reason with the exact failing command and this memo.

Until a rebuilt artifact passes the repository alignment gate for both shipped 64-bit ABIs, Android
V8 is **not 16 KB-clean** and a V8-default Android build must **not claim Google Play 16 KB
compatibility**. A QuickJS build contains no V8 and is only a separately stated rollback, not proof
that the V8 default is clean.

## Phase 1 attempt — blocked

The safe, time-boxed source-build attempt cloned Kudo's `main` at HEAD
(`fe8482757c88b7289cc92ad6888596278372c471`) into a temporary checkout and ran the upstream build
entry point:

```text
$ yarn start
yarn run v1.22.22
$ bash -c '. ./scripts/export_npm_env.sh && ./scripts/start.sh android'
./scripts/start.sh: line 8: cd: /tmp/tn-v8-prd221.2m3SQh/buildscripts/v8: No such file or directory
error Command failed with exit code 1.
```

The missing `v8/` tree is created by Kudo's `yarn setup`, which also runs `gclient sync`, installs
packages with `sudo apt-get`, and downloads Android NDK r23c. That NDK is not installed in this
lane (`/home/joao/Android/Sdk/ndk/` has 27.0.12077973 and 27.1.12297006 only), and the lane brief
prohibits unsafe external install/swap actions. No V8 artifact was produced. The concrete unblock
is an approved, reproducible V8 source-build environment (or an equivalent checked-in/hosted
builder) with the source tree, depot_tools, and a compatible NDK; then the builder must add
`-Wl,-z,max-page-size=16384 -Wl,-z,common-page-size=16384`, produce both 64-bit ABIs, and rerun
the repository gate. The emulator/V8-conformance step was not run because no rebuilt host or
aligned artifact exists.

The new dependency-flow gate rejects the existing prebuilt as expected:

```text
$ node packages/runtime-native/scripts/download-deps.mjs --only v8-android
Error: Android 16 KB alignment check failed for .../third_party/v8-android/lib/arm64-v8a/libv8android.so: LOAD alignments 0x1000 (2**12), 0x1000 (2**12), 0x1000 (2**12); expected every segment >= 0x4000 (2**14)
```

**Disposition:** `BLOCKED/requires-v8-source-toolchain/`. The Android default remains V8, but it is
not a 16 KB-clean/store-claimable V8 artifact today; QuickJS remains the explicit rollback.
