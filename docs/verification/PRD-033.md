## Browser gate

The prescribed browser command was attempted against the real platformer collect scenario,
including `xvfb-run`, `--enable-unsafe-webgpu`, and headed mode. Chromium exits before a
page is created in this managed sandbox:

```text
browserType.launch: Target page, context or browser has been closed
[pid=32][err] ... crashpad ... setsockopt: Operation not permitted (1)
[pid=32] <process did exit: exitCode=null, signal=SIGTRAP
```

Adding `--no-sandbox --disable-setuid-sandbox --no-zygote --single-process` reproduced the
same `SIGTRAP`. Therefore the real browser consumer scenarios, the per-step sampling
revert, and the platformer gameplay negative controls are setup-blocked here, not claimed
green. CI now generates a platformer scaffold and runs its committed `test` suite under
the PRD-020 WebGPU/Xvfb recipe so those gates execute on the supported runner.
