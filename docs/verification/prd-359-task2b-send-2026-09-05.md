## Native behavior

`webtransport.cpp:124-131` names the whole-write statuses and the 1 MiB
`kStreamWriteQueueLimit`: accepted writes return their complete input length,
invalid/hard-failed writes return `-1`, queue saturation returns `-2`, and a single
write larger than 1 MiB returns `-3`. `queuedStreamBytes` (`:1135-1145`) sums every
`StreamState::outBuf` with subtraction-based overflow checks. Admission happens before
`insert`, so saturation and oversized input preserve the existing buffers and do not
construct an unbounded intermediate copy.

`streamWrite` (`:1285-1310`) rejects missing/unfinished/failed/closing/closed sessions,
non-outgoing streams, requested or sent FIN, null non-empty data, queue overflow, and
single-write overflow. Empty FIN is accepted only after those checks. `createStream`
(`:1238-1281`) prebuilds its WT signal header, admits those bytes against the same
session budget before consuming a stream id. On an initial header hard failure, the
failed local map entry is erased, while the allocator remains advanced because
quiche has seen the stream id. This prevents a queued error from targeting a later
stream with a reused id; the coordinator caught and required this correction.

`pumpStream` (`:1195-1227`) keeps the prior Done/partial-write behavior: Done retains
the full buffer, a positive return erases exactly that prefix, and FIN is marked sent
only after the buffer is empty. Empty buffers release their vector storage; a partial
buffer is compacted only after its retained capacity is more than twice its remaining
size. A hard quiche error clears the pending bytes, records `sendError`, and emits
`EventType::StreamWriteError` with the stream id and quiche peer error code. A positive
send or a hard failure that releases bytes queues one session-wide
`EventType::Writable`; `Session::writableEventQueued` coalesces it, and
`processEvents` (`:1437-1446`) clears the flag when that event is popped.

The existing dispatcher maps these events at `:857-913` to `streamWriteError` with
`streamId, peerErrorCode` arguments and `writable` with no additional arguments. No
new native global was installed, and datagram drop accounting is untouched.

The wire regression at `tests/webtransport_wire_test.cpp:677-982` proves, through the
real Session and injected quiche sender:

- Done, one-byte short write, Done, and resume preserve the exact concatenated accepted
  bytes and final FIN; a positive partial write also wakes before the buffer empties.
- Two streams fill exactly 1 MiB; the next byte and an overflow on the second stream
  are refused without changing either buffer. Draining one stream allows the refused
  stream to retry successfully.
- A full queue refuses a new WT header before map insertion/id consumption, and a hard
  header send error retires its id so the next creation uses the following id.
- A single write larger than 1 MiB is refused without admission; empty FIN, post-FIN,
  failed, close-requested, and real quiche-closed writes are checked.
- Hard stream errors return failure, free storage, carry the peer error code, leave
  `droppedDatagrams` unchanged, and produce the distinct stream error plus recovery
  event. Writable events coalesce across streams and become available again after
  `processEvents` pops the event.

## Independent review

The read-only reviewer inspected native admission, the quiche pump, borrowed buffer
implementations, event delivery, failed stream-ID retirement and regression coverage.
No blocking defect remained. Minor coverage gaps: saturation assertions compare
contents rather than vector capacity, and the send seam checks FIN on the final
call rather than every attempt. Source inspection confirmed rejection precedes
insertion and pending FIN is passed unchanged. No additional runtime defect was
identified. Native pending buffers are the scope of this slice; quiche internals
and JavaScript queues are not claimed fully bounded here.
