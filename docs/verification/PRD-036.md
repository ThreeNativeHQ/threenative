## Continuation consumer proof

The continuation adds a dev-only consumer boundary in
`examples/abyss-framework/src/main.tsx`. It waits for the real scene to enter, restarts the
real Abyss game, dispatches the
checked-in `replay.playtest.json` steps at `window`, advances the real fixed-step runtime,
captures the player trace, then resets the real scene and drives the captured `Recording`
through `createReplayDriver` at the keyboard target plus the renderer's pointer target. The
closed six-key recording shape is unchanged. Replay calls `driver.prepare(runtime)` before
rebuilding the scene, so scene initialization consumes the same captured RNG stream as the
recording; gameplay spawns and placement still use `ctx.random()`. The proof compares both
1,800-tick traces, including player score, and checks mid-trace and final-state goldens.

Positive controls observed:

```text
pnpm typecheck; pnpm lint; pnpm test; pnpm budgets  PASS
pnpm tsx scripts/count-loc.ts --check               PASS (432 / 473 normalized LOC)
pnpm exec playwright test --config=/tmp/prd036-continuation.config.ts --workers=1
  2 tests PASS (22.4s; checked-in 1,800-tick CLI scenario + real record/replay trace)
```

The source recording is checked in at
`examples/abyss-framework/recordings/replay.json`, with its consumer-scoped final-position
oracle at `examples/abyss-framework/recordings/replay.oracle.json`. The built CLI converted
both with `record-to-scenario` into the checked-in
`examples/abyss-framework/playtests/replay.playtest.json`; the generated fixture uses
held-key arrays, a final release step, and `movement.reachesPositionWithin` at the captured
final position. The focused browser run consumed that regenerated fixture.

The checked-in recording was exported from that browser consumer boundary, not hand-authored:
`randomState` is `90210`, `runtime.core` is `0.1.0`, `runtime.step` is the fixed `1/60`
step, and `runtime.agent` is the captured Chromium user agent. The generated scenario copies
those five runtime fields into `assert.world.runtime`; the browser evidence reports that world
assertion as passing. A mismatched runtime fingerprint fails the world assertion closed.

The movement regression control is also observed red: temporarily changing
`const speed = 560 * dt` in `examples/abyss-framework/src/scenes/Abyss.ts` to
`const speed = 565.6 * dt` makes the **generated-scenario test itself** fail its
`movement.reachesPositionWithin` assertion: the closest observed position was
`5.693651574053697` world units from the oracle. The separate record/replay trace also fails
the mid-trace golden by `4.6533223516233875` world units and the final-position golden by
`5.597900029397351` world units. The mutation was reverted immediately.

```text
mid-trace: Expected <= 0.000001; Received 4.6533223516233875
final:     Expected <= 0.000001; Received 5.597900029397351
```

The scene-transition repair moves recording to the game loop's `beforeUpdate` hook, so the
input tick that requests a restart is captured before navigation can skip ordinary plugin
updates. Blur now clears pointer coordinates as well as keys/buttons, and the constraints test
exercises the actual replay validator rather than a test-local six-key literal.

The framework consumer also now uses `ctx.random()` for all Abyss gameplay randomness and a
fixed-step simulation clock for the attract/over animation; otherwise the same recording
would encounter host `Math.random()` and `performance.now()` and could not be deterministic.

The scoped feature-delta budget remains open and is recorded honestly: core/physics source
changed by `+288/-32`, a net `+256` lines. The global framework budget is green at 4,196 / 15,000
LOC, but `pnpm budgets` does not prove the PRD's separate ≤200-line delta gate.
