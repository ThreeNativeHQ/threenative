## Continuation consumer proof

The continuation adds a dev-only consumer boundary in
`examples/abyss-framework/src/main.tsx`. It restarts the real Abyss game, dispatches the
checked-in `replay.playtest.json` steps at `window`, advances the real fixed-step runtime,
captures the player trace, then resets the real scene and drives the captured `Recording`
through `createReplayDriver` at the same target. The closed six-key recording shape is
unchanged. `tests/browser-replay/replay.spec.ts` compares both 1,800-tick traces and checks
`tests/browser-replay/replay.golden.json` at tick 60, before the rightward clamp can hide a
movement-speed change.

Positive controls observed:

```text
pnpm typecheck && pnpm lint && pnpm test && pnpm budgets  PASS
pnpm tsx scripts/count-loc.ts --check               PASS (425 / 473 normalized LOC)
pnpm exec playwright test --config=/tmp/prd036-continuation.config.ts --workers=1
  2 tests PASS (checked-in 1,800-tick CLI scenario + real record/replay trace)
```

The movement regression control is also observed red: temporarily changing
`const speed = 560 * dt` in `examples/abyss-framework/src/scenes/Abyss.ts` to
`const speed = 565.6 * dt` makes the focused browser project fail its golden tick-60
assertion by `4.6533223516233875` world units, while the record/replay traces still match.
The mutation was reverted immediately.

```text
Expected: <= 0.000001
Received:    4.6533223516233875
```

The framework consumer also now uses `ctx.random()` for all Abyss gameplay randomness and a
fixed-step simulation clock for the attract/over animation; otherwise the same recording
would encounter host `Math.random()` and `performance.now()` and could not be deterministic.
