## Why there is a rerun at all

The 2026-08-09 live-agent exit gate **failed**, and it is not being relabelled. Its record stays at
[PRD-032-asset-proof/README.md](PRD-032-asset-proof/README.md). What it measured:

| Criterion | A: with MCP | B: without MCP |
| --- | ---: | ---: |
| Crate readability | **2/5** | **5/5** |
| Material credibility | **4/5** | 3/5 |
| Scene fit | 3/5 | 4/5 |
| Overall visual improvement | 3/5 | **4/5** |

The shape of that loss is specific and it is the reason a rerun is defensible. The MCP arm **won**
the criterion that measures the assets it fetched (material credibility) and **lost** the criterion
that measures the object it applied them to (crate readability, 2/5 against 5/5). A photoreal rust
texture on a gameplay pickup destroyed the silhouette the player needs to see. That is evidence
about *where a found photoreal asset belongs*, not evidence that the server finds bad assets.

So the capability was measured on a job where photoreal is the wrong tool. This rerun measures it
on one where it is the right tool.

## The pass condition, predeclared

**Arm A passes only if both hold:**

1. A fresh read-only critic, seeing only the two images and the sealed critic prompt, returns
   `VERDICT: A` on overall visual improvement; **and**
2. A loses no individual criterion to B by more than 1 point.

Condition 2 exists because of what 2026-08-09 found: an arm that wins overall while destroying one
criterion has not earned a capability claim, it has traded one. A 2/5 against 5/5 on any criterion
is a fail under this condition even if the overall verdict goes A's way.

**Anything else is a fail**, including a tie, a `VERDICT: B`, and a critic that reports low
confidence on a verdict for A.

### The compromised precondition — typecheck

This file required both projects to pass `pnpm typecheck` before their frames counted. **Arm A
failed it; arm B passed. The clause does not separate the arms, and here is the proof:**

A third project was scaffolded from the same tarballs with **no agent involvement of any kind**,
purely to test the template:

```console
$ npx tsc --noEmit -p tsconfig.json     # pristine scaffold, nobody touched it
14 errors in 4 files:
  src/render/effects/gradualBackground.ts   Property 'sample' does not exist on type 'Node<"vec4">'
  src/render/effects/lensDistortion.ts      (same, x4)
  src/render/effects/sparkle.ts             (same)
  src/render/worldEnvironment.ts            DenoiseNode -> Node<"vec4"> conversions, x8
```

**The starter template does not typecheck.** Arm A's `worldEnvironment.ts` is byte-identical to the
pristine file, so it inherited the defect untouched. Arm B passed only because dressing the
environment happened to make it rewrite that file. The precondition therefore measured *"did this
arm happen to rewrite the broken file"*, not *"is this arm's code sound"* — it cannot discriminate,
and no arm could have satisfied it by being correct.

Both arms' `vite build` exited 0, both scenarios passed on real hardware with zero console and
network errors, so both frames depict code that runs. The visual comparison — the thing this gate
exists to measure — is unaffected.

**This weakens the result and the weakening is stated, not absorbed.** What would remove the doubt
is one rerun of this same sealed brief once the template typechecks. That is cheap and it is the
honest next step, not a reason to discount what the critic found.
