# PRD-227 P2 — fixed-shape wrapper falsification — 2026-08-27

**Result: FAIL.** The pre-registered P2 gate requires V8's megamorphic stub-cache probe plus
name-dictionary lookup to fall below 3% of SDLThread self time. The fixed-shape implementation
measured **15.58%**. Two bounded re-derivations reduced that to **11.84%**, still above both the
gate and the 10.42% baseline. Per the PRD, Phase 3 did not start.

The address ranges are the disassembled V8 embedded-builtins ranges established in the PRD-222
symbol correction. Re-reporting the old capture with this exact tool and aggregation produced
7.2459% + 3.1777% = 10.4236%, matching that record's rounded 7.3% + 3.2% = 10.5%. This closes a
tool or denominator mismatch as the explanation for the red candidate.

`security.perf_harden` had reset after reboot; it was temporarily set to `0`. `--in-app` was
required because run-as simpleperf otherwise tried to rewrite a protected sample-rate property.
All completed captures lost zero samples.

## Falsified assumption and disposition

The doubtful assumption is that Three.js's hot megamorphic and dictionary load sites primarily
observe native WebGPU wrapper shapes. They do not move when wrappers share V8 ObjectTemplates and
internal fields. The new JS frame recorder itself can worsen them through deliberately generic
sites, but removing the two measured generic sites still leaves the original tax intact. The
remaining owner is Three.js's node-material shader graph, not the ThreeNative bridge. A second
diagnostic APK enabled V8's IC log and captured 139,373 `LoadIC`/`KeyedLoadIC` records. After a
30-second startup cutoff, its most frequently repeated megamorphic (`N,N`) sites were:

| Bundle site | Repeats | Source owner |
| --- | ---: | --- |
| `main.js:52440` `.type` | 733 | `three/src/nodes/core/Node.js`, `Node.getNodeType()` |
| `main.js:52594` `._beforeNodes` | 724 | `three/src/nodes/core/Node.js`, `Node.build()` |
| `main.js:80296` `.isGlobal` | 700 | `three/src/nodes/core/NodeBuilder.js`, `NodeBuilder.getDataFromNode()` |
| `main.js:52601` `.buildStages` | 655 | `three/src/nodes/core/Node.js`, `Node.build()` |
| `main.js:52382` `.updateType` | 635 | `three/src/nodes/core/Node.js`, `Node.getUpdateType()` |
| `main.js:52374` `.id` | 628 | `three/src/nodes/core/Node.js`, `Node.getHash()` |
| `main.js:52261` `.global` | 608 | `three/src/nodes/core/Node.js`, `Node.isGlobal()` |
| `main.js:52592` `.getShared` | 575 | `three/src/nodes/core/Node.js`, `Node.build()` |

The next tier is the same population: `getUpdateBeforeType`, `getUpdateAfterType`, `setup`,
`updateReference`, `getHash`, `generateNodeType`, and `getUpdateType` on heterogeneous Three.js
node subclasses. The ordinary Object3D `matrixWorldNeedsUpdate` site had 164 repeats in the same
window, and no native WebGPU wrapper site appeared among the dominant steady-state records.

A separate V8 CPU profile over the same game recorded 44,657 samples. Its leading JavaScript self
owners were Three.js `updateMatrixWorld` (8.82%), `_renderObjectDirect` (8.35%), game update
(7.33%), node-material `_update` (4.50%), and `_draw` (4.30%). The frame recorder's descriptor
serialization closure was 4.17%; its now-specialized upload function was 0.18%. IC event counts are
not cycle shares, so this profile does not assign the simpleperf 11.84% directly. Together they do
source-resolve the hot JavaScript population and reject native wrapper shape as its owner.

No third speculative shape edit follows this result. The two recorder specializations stay because
each independently reduced the pre-registered owner and kept the packed-stream tests green. The
ObjectTemplate change remains independently revertible, but it has not earned a device-performance
claim. Optimizing Three.js's renderer internals in the native host would violate the ownership rule:
Three.js remains the renderer, while `runtime-native` owns the platform seam. Phase 2 is therefore
falsified rather than eligible for another host-side implementation attempt.

## Device-state and stability limits

Doctor before the first arm reported discharging, thermal status NONE, 30.6 °C, and 49% battery —
one point below the measurement-lane minimum. The repeated diagnostic arms ended at 42% and
38.4 °C. P2 is a relative symbol-share falsification rather than the Phase 3 fps acceptance, but
none of these arms qualifies as Phase 3 evidence.

The first installed candidate also hit one physical-device SIGSEGV after about 1,100 frames in
V8's optimizing compiler (`IdentityMapBase::Clear` / `OptimizingCompileDispatcher`). Later arms
survived their captures. The existing physical Pixel stability question remains open; this session
does not attribute the intermittent crash to one PRD-227 commit.
