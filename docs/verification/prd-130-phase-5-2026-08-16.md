# PRD-130 Phase 5 — V8 is correct on the phone, not only fast

2026-08-16. [PRD-130](../PRDs/batch-26-08-16/PRD-130-android-default-js-engine.md) Phase 5, which
holds a **veto** on the flip: if V8 fails a row QuickJS passes on the same device, the default does
not change.

**It did not fail one. The veto is not exercised.**

PRD-118 proved V8 fast and never proved it correct. A default engine that renders fourteen times
faster and gets one binding wrong is worse than the slow one.

## 1. The engine is read from the process, never from the flag

New in `verify-android-first-proof.mjs`: `--expect-engine v8|quickjs`, which reads
`JS engine created: <name>` — logged by `runtime.cpp:450` on every launch — and fails when it
disagrees. `jsEngine` is now written into every report unconditionally, whether or not the run asked.

**This exists because the two came apart once already.** PRD-118 §2 records `-DMYSTRAL_USE_V8=ON`
being accepted on the command line, silently ignored, and reported back as `V8=OFF`. Every
measurement taken in between described QuickJS while its author believed otherwise. A build flag says
what was asked for; only the running process says what launched.

The gate also now *builds* the engine it asserts (`-PthreenativeJsEngine=<engine>`). A gate that
asserts an engine it did not build asserts against whatever the default happens to be that week.

## 2. Both engines pass, same device, same day

Pixel 8 `37251FDJH0037Z`. Each run built, installed, launched, waited for the exact ready marker, ran
300 frames, captured a screenshot, and required the process to stay alive 3 s afterwards.

| Run | Engine reported | Result | APK |
| --- | --- | --- | --- |
| `--expect-engine v8` | **V8** | PASS — 300 frames, clean logs, pid 6696 alive | 211,910,388 B |
| `--expect-engine quickjs` | **QuickJS** | PASS — 300 frames, clean logs, pid 7296 alive | 218,627,505 B |

Three.js 0.185.1 in both, WebGPU render path, screenshot 2400×1080 non-blank.

**Parity holds: every row QuickJS passes, V8 passes.** No row is blocked and none is omitted.

### Multitouch, on the emulator it requires

`verify-android-multitouch.mjs` refuses a physical serial by construction —
`TN_MULTITOUCH_EMULATOR_REQUIRED: protocol-B injection requires an emulator-* serial` — so it ran on
`emulator-5554` (x86_64, API 35), which after Phase 1 can run V8 at all:

```
JS engine created: V8
{"pass": true, "latches": {"maxPointers": 2, "movedWithTwoPointers": true,
                           "leftGroundWithTwoPointers": true, "airborne": true}}
```

Two simultaneous pointers tracked, movement under two pointers, and the jump latch — under V8, on
the ABI that had never run V8 before today.

## 3. Negative control — observed red on hardware

The control the whole assertion exists for: a QuickJS build, with the gate asking for V8. A parity
gate whose two sides can be the same build measures nothing.

```sh
$ ./gradlew :app:assembleDebug -PthreenativeJsEngine=quickjs   # 0 V8 artifacts in the APK
$ node scripts/verify-android-first-proof.mjs --device 37251FDJH0037Z --expect-engine v8 --skip-build
exit 1
FAIL: Engine mismatch: asked for v8, the running process reported QuickJS.
      The installed APK is not the engine this gate is measuring.
```

Five unit tests cover the same boundary without a device, including the case that matters second
most: a process that **never reported** an engine is a distinct failure from one that reported the
wrong engine, because the causes differ — a crash before engine creation, against a build that
shipped the wrong engine.

## 4. A cost finding that contradicts the accepted price

PRD-130's status block accepts V8 "for +25.6 MB of arm64 payload", taken from PRD-118 §4, which
summed uncompressed native libraries.

~~**Measured on the artifacts built today, the V8 APK is 6.7 MB _smaller_ than the QuickJS one**
(211,910,388 B against 218,627,505 B)...~~ **Withdrawn the same day — that was a build artifact, not
a measurement.** Building one engine after the other reuses the previous APK file, and the space the
removed library occupied stays in it as dead bytes, so the QuickJS APK was carrying V8's ghost.

Packaged from clean outputs, per ABI: **V8 costs +25.6 MB on arm64** (76,690,124 B → 102,297,258 B).
The price the owner accepted is confirmed, not contradicted.
[`android-engine-size-2026-08-16.md`](./android-engine-size-2026-08-16.md) has the four numbers and
the trap.

## 5. What this does not claim

- **Not a performance result.** No frame timing is reported here. That is the load test's job.
- **Not full conformance.** `conformance/run-conformance.mjs` was not executed under V8; the rows
  proved are the first-proof gate and multitouch. Any conformance row not run is not a passing row,
  and PRD-130's Phase 5 is complete only when that suite has run under both engines.
- **Not mobile-ready.** One phone, one emulator.
- **Not a signed-artifact claim.** Debug builds throughout; the release type still has no
  `signingConfig`, which is PRD-128's row.
