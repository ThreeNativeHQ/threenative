# PRD-020 verification — phases 1–5

Date: 2026-08-06

Status: implementation complete. The capture, blind image bundle, and judge validator are
implemented and exercised against the archived pair. The authoritative human visual
benchmark remains intentionally separate from this instrument result.

## Capture guard

`scripts/capture-guard.ts` decodes PNGs with `pngjs` and rejects uniform, transparent,
low-variance, and HUD-only frames with `TN_CAPTURE_BLANK`. Its live thresholds are 8 distinct
colors, 0.01 luminance standard deviation, and 0.05 bright-pixel ratio.

Focused command: `pnpm exec vitest run scripts/__tests__/capture-guard.spec.ts`

Result: PASS — 1 file, 6 tests, including a checked-in vanilla frame control.

The first live framework capture exposed a false negative in the initial guard: 702 colors
and 0.02486 luminance deviation passed, although the screenshot visibly contained only HUD
text over an empty field. The bright-pixel criterion was added; the HUD-only synthetic test
and the real vanilla fixture both pass their respective controls.

## Blind image and judge proof

Command: `pnpm tsx scripts/score-blind.ts --image ... --out <bundle> --reveal <external-path>`

Result: PASS — two generic `sample-NN/image.png` files and `bundle.json` were written; the
reveal map was written outside the bundle. A PNG `tEXt` chunk containing `@threenative` was
removed, and the bundle contains no arm identifiers.

Command: `pnpm sweep:judge <bundle> --input <fresh-critic.json>`

Result: PASS on the fresh archived pair; `judge.json` contains bounded 1–5 scores, evidence,
biggest gaps, and a comparison verdict. Both samples were screenshot-worthy. The critic
scored sample-01 at playability 4 / visuals 3 and sample-02 at playability 3 / visuals 4,
with sample-01 better at medium confidence. The result is an instrument signal, not the
authoritative benchmark result.

The protocol now labels judge output as an instrument score and explicitly keeps it from
satisfying the authoritative human visual benchmark.
