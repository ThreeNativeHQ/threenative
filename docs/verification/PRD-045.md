# PRD-045 verification — 2026-08-08

## Proven in the current main tree

The transport seam and fail-closed device path were exercised without changing the scenario
format:

```text
pnpm typecheck                                      PASS
pnpm lint                                           PASS
device-playtest.spec.ts                             PASS — 5 tests
device-transport.spec.ts                            PASS — 3 tests
```

The in-process device proof covers a passing movement assertion, a deliberately wrong value
(exit code 1), a missing bridge (exit code 2), a misspelled assertion rejected before launch,
and an explicit unsupported network assertion. The transport tests correlate a real HTTP poll
request with its response, validate endpoint restrictions, and exercise the Android `adb`
mailbox ready handshake and request/response correlation.

## Android emulator proof — 2026-08-08

`emulator-5554` ran `device-smoke.playtest.json` unchanged after the current catalog-version
bundle was rebuilt. Chromium and Android both evaluated `visibility.cube` and returned pass.
The Android run used the adb mailbox transport and captured a nonblank 1080×2400 screenshot.

The fail-closed controls produced the required results on the Android target:

```text
device-smoke-wrong-value.playtest.json     exit 1  TN_PLAYTEST_VISIBILITY_FAILED
device-smoke.playtest.json, bridge absent exit 2  TN_PLAYTEST_BRIDGE_MISSING
device-smoke-misspelled.playtest.json      exit 2  TN_PLAYTEST_SCENARIO_INVALID
device-smoke-network.playtest.json         exit 2  TN_PLAYTEST_UNSUPPORTED_ON_TARGET
```

The first wrong-value run exposed that `present: true` returned before evaluating
`minProjectedPixels`; it incorrectly exited 0. `assertions.ts` now evaluates both constraints,
a focused regression test covers the combination, and the same emulator scenario exits 1.
The missing-bridge APK is reproducible with `THREENATIVE_PLAYTEST_BRIDGE=disabled`; the normal
bridge-enabled APK was rebuilt and reinstalled after the control.

The repository `pnpm test` run reached 146 passing files and 1,111 passing tests but failed four
duplicate workspace suites while the recursive playtest package test rebuilt its `dist/` entry;
the failure was `Failed to resolve entry for package "@threenative/playtest"`. This is recorded
as a repository gate failure, not converted into a pass.

## Repository gate follow-up — 2026-08-08

The workspace test command was serialized in commit `51af406` so recursive package tests no
longer rebuild the playtest distribution concurrently. The current full gate passes:

```text
pnpm typecheck && pnpm lint && pnpm test && pnpm budgets  PASS
pnpm test                                                    PASS — 150 files, 1,160 tests
```

This closes the repository verification issue and the Android Phase 3 negative-control gate.
The real driver uses the same mailbox transport that the Android native bridge exposes; it
does not depend on the currently stubbed Android HTTP client. iOS device transport remains
open.
