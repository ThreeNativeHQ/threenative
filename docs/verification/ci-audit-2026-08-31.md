## Structural doors before PRD-303

Commands and output:

```text
$ grep -rl 'schedule:' .github/workflows/

$ grep -rn 'test:templates' .github/
.github/workflows/ci.yml:178:      # scenarios keep their gate in `pnpm test:templates`, which has hardware.
```

No scheduled trigger or executable `test:templates` caller existed.

The PRD recorded KVM as absent from `native-platforms.yml` at `1c2f1550`. Current `origin/main`
already contains the provisioning change:

```text
$ grep -n '99-kvm4all.rules' .github/workflows/native-{platforms,release}.yml
.github/workflows/native-platforms.yml:95:            | sudo tee /etc/udev/rules.d/99-kvm4all.rules
.github/workflows/native-release.yml:481:            | sudo tee /etc/udev/rules.d/99-kvm4all.rules
```

Both execute the same udev rule, reload, and trigger commands. The platform lane then reports
`TN_EMULATOR_ACCEL:kvm` or `TN_EMULATOR_ACCEL:software`; unlike release, it deliberately does not
end on `test -w /dev/kvm`. The existing structure test requires reporting rather than turning a
hosted runner without writable KVM into a pre-emulator failure. PRD-303 therefore preserves the
landed behavior and asserts parity of the three provisioning commands, not identical tail logic.

## Golden-path split contract

Command:

```sh
grep -n 'GOLDEN_PATH_STEPS\|TN_GOLDEN_PATH_TEMPLATES' scripts/verify-golden-path.ts
```

`verify-golden-path.ts` asserts this exact per-run plan:

```text
pack → scaffold → install → mcp → dev → test → build web → assert artifact
```

`pack` is global; the remaining seven steps execute for every template selected by
`TN_GOLDEN_PATH_TEMPLATES`. The verifier also runs the packed-dependency mutation control after
the selected templates. Therefore a two-leg `starter | platformer` matrix can run
`pnpm verify:golden-path` in each leg with `TN_GOLDEN_PATH_TEMPLATES` set to that leg; no verifier
step or packed mutation control is orphaned.
