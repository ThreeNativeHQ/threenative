# PRD-290 verification — 2026-08-31

## Scope established from the PRD

This lane covers the web failure surface in `@threenative/ui`, generated template presentation, the
playtest seam needed to force a deterministic renderer failure, and the native host's observed
failure path. The current base already removed the old launch card and canvas-only poll in
`9c4a30b1`; this lane did not restore either one. The remaining browser gap was the unstyled error
and the minimal template's uncaught `game.start()` rejection.

The repository currently ships eight templates, not the seven named by the PRD: `action-rpg`,
`defense`, `minimal`, `platformer`, `racing`, `sailing`, `shooter`, and `starter`.

## Phase 0 — before the implementation

observation window. The pre-renderer probe made both WebGL context creation and
`navigator.gpu.requestAdapter()` return no adapter. The post-renderer probe allowed the renderer to
start and aborted the hashed `native-proof.*.glb` request.

## Proof added

- Every generated template owns a restyleable `[data-threenative-canvas-error="true"]` rule. The
  package supplies only the element and stable `id="threenative-canvas-error"`; it owns no visual
  styling.
- The minimal template catches `game.start()` and replaces `#app` with the same failure element.
- The playtest schema has a deterministic browser-only `bootFailure: "renderer-no-adapter"` seam and
  a HUD `visible` assertion. Visibility samples the rendered box and checks the viewport-centre
  element is the node or one of its descendants, so a DOM node hidden behind an opaque overlay fails.
- `starter/playtests/boot-failure.playtest.json` asserts the thrown message, rendered visibility, a
  nonblank screenshot region, and explicitly documents the expected renderer console error.

The focused red run was:

```text
pnpm exec vitest run packages/ui/__tests__/game-canvas.spec.tsx packages/playtest/__tests__/sampling.spec.ts
2 failed, 9 passed
```

After the implementation, the focused suite passed with 64 tests across five files. The generated
starter sweep then ran 24 scenarios, including `boot-failure`, and ended with
`{"scenario":"boot-failure","pass":true}` and overall `"pass": true`.
