Status: implementation and lane evidence recorded on 2026-08-31.

Baseline: `7e5a9fe1` (the PRD measurement baseline). Lane baseline before this

## Scope and layer

The feature is split at the engine boundary. Generated game source owns the
probe-volume look and sampling expression; `@threenative/core` owns the
WebGPU scheduling, atlas mechanism, lifecycle, and stale observation; the
native runtime forwards the 3D render-pass depth slice needed by the same
WebGPU path on native. The fixture and conformance scene prove the public
surface rather than adding gameplay to a package.

## Negative controls

Every declared mutation was observed red and restored before delivery:

1. Returning zero from the sample node: the on-arm playtest exited 1 and
   logged `TN_PROBE_SAMPLE` with `[0,0,0]` and `hueRatio=0`.
2. Importing `three/addons/lighting/LightProbeGrid.js`: the packaging spec
   exited 1 and reported `render/probe-volume.ts` as the offending source.
3. Setting `ATLAS_PADDING=0`: the probe-volume suite exited 1 at the padded
   edge assertion (`expected ... toEqual ...`); 6 of 7 tests passed.
4. Baking synchronously: the render-budget test exited 1 after observing one
   frame, `bakeCostMs=56`, and `completed=62/62`.
5. Clamping malformed density: the malformed-density test exited 1 because
   construction did not throw.
6. Dropping the stale field: the unbaked-sample test exited 1 because
   `stale` was false instead of true.
7. Running native before depth-slice forwarding: conformance produced WebGPU
   validation errors, including `depthSlice is required for a 3D attachment`
   when it was undefined. The corrected native run has no GPU validation
   errors and passes the selected row.
