# PRD-254 — PRD-222 stopped-lane audit (2026-08-30)

## Result

The three-commit `worktree-prd-222-resume` branch contains real missing work and is safe to land as
PRD-222 Phase 1, not as a completed PRD. Main still declared only eight Android configuration axes;
the lane adds `smallestScreenSize`, `fontScale`, `locale`, `layoutDirection`, and `colorMode`, plus
a fail-closed contract and the device probe/evidence that motivated it.

The layer is `packages/runtime-native`: Android activity recreation is a platform seam a portable
game cannot handle itself. The change does not decide appearance.

failed with:

```text

process instead of resizing (PRD-222).
```

focused assertions, and `prd-222-resume-probe.mjs` passed Node syntax checking.

The complete runtime-native JavaScript suite reported **620 passed, 39 skipped, 4 failed**. All

twice and timestamp-query binaries for V8 and QuickJS. None executed or named the Android manifest

declaration outputs for playtest/assets, core, then physics; the doubtful assumption was that a
fresh worktree's root gates self-provision package `dist` outputs. Root lint and root test therefore
did not execute as a chain and are **UNVERIFIED**; the focused 7/7 and 620-test runtime result above
are the gates actually run.

Root `pnpm lint` did execute independently and exited 0. It reported the repository's existing
warning backlog, including the probe's complexity warning, but no lint error.

## Fresh device-run limit

`adb devices -l` found only `emulator-5554`. Its installed Bayview APK was confirmed to be the old
red control: packaged `configChanges=0x17f0`. A fresh APK build against the audit worktree stopped
after three setup attempts:

1. Source build fell back to the unpublished prebuilt manifest and received HTTP 404 because the
   worktree had no Android dependencies.
2. `download-deps.mjs --android` downloaded the set but correctly rejected the pinned V8 arm64
   library for 4 KB rather than 16 KB load alignment.
3. The documented QuickJS x86_64 rollback advanced into CMake, then failed because the Android
   dependency set had not provisioned `third_party/stb/stb_image.h`.

The doubtful assumption was that the Android downloader produced a build-complete fresh source
tree. No fourth workaround was attempted, no APK was installed, and no new emulator or physical
green is claimed. This setup limitation does not erase the branch's committed emulator A/B; it is
recorded so the next PRD-222 device round starts by repairing dependency provisioning rather than
misattributing a host-build failure to the manifest change.

The detached tarball mini-game protocol does not apply to this internal Android activity contract.
Its observable consumer boundary is the packaged manifest plus a real Android activity lifecycle;
the branch carries that emulator proof and the current audit inspected it directly.
