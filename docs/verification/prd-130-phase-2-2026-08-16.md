# PRD-130 Phase 2 — Android V8 is reconstructible from the supported path

2026-08-16. [PRD-130](../PRDs/mobile/PRD-130-android-default-js-engine.md) Phase 2.

**Before this, `third_party/v8-android/` existed on exactly one machine because somebody unpacked it
by hand.** `download-deps.mjs` is the package's only supported dependency reconstruction path — its
own `AGENTS.md` says so — and its `androidDeps` list was `sdl3`, `wgpu-android`, `sdl3-android`,
`quiche-android`. A fresh checkout could not build Android V8 at all, which makes a V8 *default*
unshippable regardless of the numbers.

## 1. What was added

`v8-android` joins `androidDeps`, pinned:

| | |
| --- | --- |
| Source | `github.com/Kudo/v8-android-buildscripts` `v11.110.1`, `v8-android-jit.zip` |
| Archive sha256 | `b2bc1fc317265163becbf0abe914d44b7d546448bb1aafe921a25e8ba4839a26` |
| ABIs provisioned | `arm64-v8a`, `x86_64` — the same two `abiFilters` ships |

The `-jit` archive is the one that matters and the name is not incidental: a JIT-less V8 would
reproduce the problem PRD-118 exists to solve.

**Checksum verification is new and general.** `downloadDep` now verifies any dependency that declares
`sha256` and deletes the archive on mismatch rather than extracting it. Only `v8-android` declares
one today; nothing else changed behaviour.

**`reshapeV8Android` unwinds the archive**, which nests three deep — zip → `dist.tar` → an AAR
holding the libraries, with headers and snapshots in a third place. It produces exactly the three
things the build reads and throws naming the ABI if any is absent, then deletes ~1 GB of build
leftovers, unstripped libraries and ABIs this repository does not ship. **Result on disk: 60 MB.**

## 2. Proved by reconstruction, not by reading

The hand-placed tree was moved away entirely and rebuilt by the script alone:

```sh
$ mv packages/runtime-native/third_party/v8-android /elsewhere
$ node packages/runtime-native/scripts/download-deps.mjs --only v8-android
Verified v8-android archive checksum
Installed v8-android 11.110.1 for arm64-v8a, x86_64
  v8-android: OK
```

**All four artifacts are byte-identical to the hand-placed originals:**

| Artifact | sha256 |
| --- | --- |
| `lib/arm64-v8a/libv8android.so` | `eddea92d4cea2ac34e373629327c6293981444fdaf93f8b16986a17effd33124` |
| `lib/x86_64/libv8android.so` | `e691332f558e528a49319e32c51df170be17824e623388a417900a60601701d8` |
| `snapshot_blob/arm64-v8a/snapshot_blob.bin` | `8fc946b2d1c7147de02f3f38dee20b178eb66fc30e69e573dbb20d9849c1dd3a` |
| `snapshot_blob/x86_64/snapshot_blob.bin` | `90b174978868b0782d23b097af6ab17f50bb8695d3262fdc31b014e8b79391f0` |

The hand-placed copy has since been deleted. **What is on disk now is what the script produced**, and
the APK below was built from it — so this is not a comparison against a tree that is still quietly
doing the work.

```sh
$ ./gradlew assembleDebug -PthreenativeJsEngine=v8
```

## 3. Negative control — observed red, exit 1

The one that matters: with the dependency absent and the download script **not** run, the build must
fail loudly. A quiet fall back to QuickJS here is the silent-substitution failure PRD-118 §2 spent
three separate checks ruling out — and it would be invisible, because the APK would install, launch
and work.

```sh
$ mv packages/runtime-native/third_party/v8-android /elsewhere
$ ./gradlew assembleDebug -PthreenativeJsEngine=v8
exit 1
* What went wrong:
Some problems were found with the configuration of task ':app:copyV8Snapshot' (type 'DefaultTask').
  - Property '$1' specifies file '.../third_party/v8-android/snapshot_blob/arm64-v8a/snapshot_blob.bin'
    which doesn't exist.
    Reason: An input file was expected to be present but it doesn't exist.
```

It refuses, and it names the file. **It does not build a QuickJS APK and call it V8.**

## 4. What this does not claim

- **Not a default change.** Everything here was built with an explicit `-PthreenativeJsEngine=v8`.
- **Not a CI claim.** The download ran on this machine, once. No hosted runner has executed it.
- **Not a guarantee the upstream release persists.** It is a third-party GitHub release; the pinned
  checksum makes substitution detectable, not impossible. If it disappears, the dependency has to be
  rehosted, and the checksum is what makes that a decision rather than a surprise.
