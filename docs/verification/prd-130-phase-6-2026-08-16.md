# PRD-130 Phase 6 — the Android default is V8, and this is what it bought

2026-08-16. [PRD-130](../PRDs/mobile/PRD-130-android-default-js-engine.md) Phase 6. The
decision was the product owner's, taken 2026-08-16; this is its execution and its price.

**A build with no engine flag now launches V8 on the Pixel 8, read from logcat.** The rollback was
exercised in the same session, not asserted.

## 1. Three sites, all flipped, and a guard that they agree

| Site | Was | Is |
| --- | --- | --- |
| `CMakeLists.txt` Android platform block | `MYSTRAL_USE_QUICKJS ON` unless V8/JSC asked for | `MYSTRAL_USE_V8 ON` unless QuickJS/JSC asked for |
| `android/app/build.gradle.kts:38` | `.orElse("quickjs")` | `.orElse("v8")` |
| `CMakePresets.json` `tn-android` | `MYSTRAL_USE_V8: OFF`, `QUICKJS: ON` | `V8: ON`, `QUICKJS: OFF`, and the display name no longer says QuickJS |

PRD-130 warns that a preset contradicting the platform block "is how the flag came to work on one
machine only". `runtime-next-contract.test.mjs` now asserts all three agree.

**Control observed red:** reverting only the preset to `MYSTRAL_USE_V8: OFF` while the other two say
V8 fails with *"the tn-android preset must select V8"*. The disagreement is caught rather than
letting the build pick a winner depending on whether it went through Gradle, the preset, or a bare
CMake configure.

A second test keeps the rollback reachable — the property still accepts `quickjs`, the flag is named
where anyone editing the file will see it, and the CMake option still exists.

## 3. What the default buys, measured tonight

Both arms built from the **same load-test bundle** (16,384 moving cubes, 3 draw calls, 196,611
triangles), the same APK pipeline, the same device, minutes apart — differing only in the engine
flag. This is not PRD-118's number re-quoted; it is a fresh paired A/B on the default that now ships.

| Rung | V8 (no flag) | QuickJS (rollback) | Ratio |
| --- | --- | --- | --- |
| L2 @ 4,096 | 8.27 ms | 20.61 ms | 2.5× |
| L3 @ 4,096 | 8.29 ms | 22.65 ms | 2.7× |
| L2 @ 16,384 | 8.21 ms | 84.29 ms | **10.3×** |
| L3 @ 16,384 | **8.34 ms** | **101.24 ms** | **12.1×** |

**Read the V8 column as a ceiling, not a measurement.** The host presents `fifo vsync=true` at
120 Hz, so 8.33 ms is the frame interval and V8 sits on it at every rung across a 4× load range —
its work *fits inside one frame* and the real figure is lower. The vsync-off diagnostic puts the
same rung at 5.91 ms. QuickJS at 101.24 ms is nowhere near the interval and is a real measurement,
so **every ratio above is a lower bound**.

The knee tells the same story without any arithmetic: at a 20 ms p95 threshold V8 reaches 16,384 in
both modes, and QuickJS does not clear the *first* rung.

Godot 4.7.1's Android export produced 39.27 ms on this device and scene on 2026-08-14. QuickJS was
2.6× slower than that; V8 is comfortably faster.

### The condition block, and one honest caveat

Both reports carry what PRD-127 landed hours earlier:

```
device condition: battery 80%, charging, thermal NONE, screen on
provisional: charging
```

**The phone was on USB and both runs are stamped `provisional: ["charging"]`.** The preflight refused
outright until `--allow-low-battery` was passed, which is the escape working as designed — the
override does not hide the condition, it writes it into the report. A charging phone runs warmer and
throttles differently.

This does not put the conclusion in doubt: both arms were charging, at the same 80%, at thermal
NONE, minutes apart, so the comparison is like-for-like and a 12× gap is not a thermal artifact.
**It does mean these two numbers are not final.** A discharging retake is one command once the cable
is out, and it is the one step of this phase not yet taken.

## 4. Cost, restated

- **+30 MB of arm64 library.** `libv8android.so` is 29,919,888 B, plus `libc++_shared.so` and a 45 KB
  snapshot per ABI. V8 needs the shared STL, so the whole runtime links it.
- ~~**The APK measured smaller, not larger**~~ — **withdrawn the same day.** That comparison was
  between two universal APKs built one after the other, and incremental packaging left the earlier
  engine's library as dead bytes in the later file. Packaged from clean outputs, per ABI, **V8 costs
  +25.6 MB on arm64 and +26.1 MB on x86_64** — confirming the price the owner accepted rather than
  contradicting it. [`android-engine-size-2026-08-16.md`](./android-engine-size-2026-08-16.md).
- **Operationally:** an external snapshot per ABI that must match its slice, a shared STL in the APK,
  and a third-party GitHub release in the dependency graph.

## 5. What this does not claim

- **Not mobile-ready.** One phone, one emulator, one vendor, one GPU family. iOS is untouched and
  stays JSC.
- **Not a finished PRD-130.** Phase 3 (per-ABI download size) and Phase 4 (the prebuilt/release path)
  are **not done**, and until Phase 4 lands the new default only reaches operators who compile the
  runtime — a scaffolded user building from `android/prebuilt/` still gets QuickJS, because that path
  ships no V8 at all. That is the largest open gap and it is named here rather than left implicit.
- **Not a discharging measurement.** §3.
- **Not a signed-artifact claim.** Debug builds; the release type still has no `signingConfig`.
