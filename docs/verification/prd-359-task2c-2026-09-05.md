## Ownership and mechanism

The engine owns hostname resolution because games cannot portably move an OS
resolver off the native game thread. Capability search for native asynchronous
DNS returned `ThreePlaytestPhysicsRecorder`; its detail describes physics
observations, not address resolution. No reusable resolver was found. The
existing libuv loop is unavailable on Android/iOS, so this implementation uses
one process-lifetime pool with two workers and at most 64 queued/active jobs.

Workers own only hostname, port, cancellation state and copied address results.
The game thread retains session, socket, quiche and JS ownership. Completed jobs
are consumed with release/acquire ordering. Closing removes queued work and
marks active work cancelled; runtime shutdown advances a process-wide epoch.
Resolution and candidate attempts share the original 30-second connection
deadline. Address candidates are limited to 16; numeric endpoints avoid DNS.

Portable `getaddrinfo` cannot be interrupted. An active OS lookup may outlive
close or the connection deadline; it retains its own pool/job state and cannot
publish into a destroyed session. If both OS lookups never return, subsequent
hostname connections expire or reach bounded admission refusal, while game
frames continue. This is an explicit resolver limitation, not a claim of OS
request cancellation or successful networking under a stuck resolver.

Review found IPv6 authority brackets were lost when parsing the address. An owned
Go listener at `[::1]:56655` reproduced `WebTransport CONNECT rejected with status
400`, exit 1 (`/tmp/prd359-dns-ipv6-before-authority.log`). Re-bracketing only the
HTTP/3 authority and Origin repaired the live path. Independent owned ephemeral
IPv4 and IPv6 fixtures each returned exactly 65,536 bytes plus FIN, exit 0:
`/tmp/prd359-dns-ipv4-green.log` and `/tmp/prd359-dns-ipv6-green.log`.
A separate `::1,127.0.0.1` forced candidate run also returned exact 64 KiB plus FIN,
exit 0 (`/tmp/prd359-dns-fallback-green.log`). These use the explicit development
self-signed override and do not qualify trusted TLS.

The process-only `MYSTRAL_WEBTRANSPORT_TEST_DNS_DELAY_MS` (decimal 0–2000) and
`MYSTRAL_WEBTRANSPORT_TEST_DNS_ADDRESSES` (at most 16 comma-separated numeric
addresses, at most 1024 characters) affect only `networking-test.invalid`.
Values are validated and copied before admission; real game hostnames ignore
these fixture controls. The original hostname remains the TLS peer name.
`runScript` clears inherited controls and fails on nonzero or timed-out exits.

Root corrected Luna's late-result test: it originally used a 2000 ms delay and
returned when local cleanup first reached zero, before DNS completion. It now
uses 500 ms and always waits 700 ms after close before its final observation.
The C++ contract independently waits for the actual active worker count to reach
zero; these two tests together prove cleanup after completion. Live elapsed time
alone is not claimed as proof of worker completion.

Review also found bracketed non-IP hosts and port suffixes were admitted. Direct
native bridge regressions failed the surface contract, CTest exit 8
(`/tmp/prd359-dns-url-red-contract.log`), before strict IPv6-literal and decimal-port
validation. The pool handle itself is intentionally immortal so global session
destruction cannot reference a destroyed function-static shared pointer.

The initial complete required live suite passed 22/22, exit 0
