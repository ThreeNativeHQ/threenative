# PRD-323 Phase 6 — the git-history decision

Measured 2026-09-02 (Phase 6's gate: the measured packed size behind the decision):

```
$ git count-objects -vH | grep size-pack
size-pack: 194.01 MiB
```

## Decision: declined

History is not rewritten. The measured win is bounded and the hazard is not:

- **The measurable win is small.** Deleting the uncited trees from `HEAD` (the owner-checkpointed
  phases, if approved) removes at most the ~280 MB they hold *as loose objects going forward*;
  the packed history keeps every historical blob regardless. `git gc --aggressive` may reclaim
  some, but the packed size only drops materially if the deleted objects are unreachable from
  every ref — and PRD-323's own lifecycle keeps cited artifacts, indexed entries and (under the
  PRD) the sweep index, so most of the 194 MB stays reachable through history regardless.
- **The hazard is out of proportion.** A history rewrite on a repository with a published
  remote, concurrent agent lanes (this session itself interleaved with two), and an
  owner-dependent checkout means every lane re-clones or rebases through a forced update. The
  batch README's own standard — provable on this machine with no human in the loop — does not
  apply to rewriting shared history.
- **The budget gate already stops the growth**, which was this PRD's own stated fallback win:
  the bloat stops growing at the commit that causes it even before any byte is reclaimed.

If the measured win is ever wanted, the prerequisite is a whole-repo lane with the remote
unpublished and every lane stopped — an owner decision this record does not reopen.
