# PRD-038 verification evidence

Date: 2026-08-08
Lane: `linchpin/prd-038-gpu-transport-and-acceleration`

## Consumer gate

A disposable project was copied from `packages/create-threenative/templates/starter`.
It installed the declared `three-mesh-bvh@0.9.14` artifact beside the workspace package
links and ran the exact checked-in `playtests/pick.playtest.json` with a fresh Brave
150.1.92.143 profile on the real X11 display.

The direct capability probe returned:

```text
navigatorGpu: true
adapter: true
webgpuContext: true
adapterInfo.architecture: "swiftshader"
pageErrors: []
```

The adapter is software WebGPU; this proves the WebGPU consumer path, not hardware
performance. The exact playtest passed with:

```text
hovered: "" -> "sculpture"
fastPicks: 310 (required >= 50)
consoleErrors: 0
networkErrors: 0
runtimeDiagnostics: 0
pass: true
exit code: 0
```

The screenshot was non-blank and showed the sculpture, lighting, particles, and the HUD
label `HOVER sculpture`.

## Observed red control

Removing only `target.geometry.computeBoundsTree()` from the disposable scaffold kept
hovering green but returned:

```text
fastPicks: 0 (required >= 50)

pass: false
```

The scaffolded project typechecked and built after repairing the pre-existing

## Isolated scaffold release check

A fresh copy of the starter template was built and exercised on disposable port `4193` with
`xvfb-run`, headed WebGPU, and the exact ten scenario names currently present in the starter
test script. Eight passed: `play`, `monitoring`, `restart`, `buffer`, `pause`, `respawn`,
`seed`, and `pick`. Two pre-existing assertions failed: `coyote` kept `coyoteJumps` at `0`
instead of `1`, and `look` measured camera separation `9.503` against a `9.5` limit. Both
failures had zero console errors, zero network errors, and zero runtime diagnostics.

The required removal proof used the same disposable scaffold after deleting `src/pick.ts`, its
import and call, the `three-mesh-bvh` dependency, and the `pick` scenario from the test script.
The script count changed from 10 to 9 and the scaffold still built. Seven of the nine remaining
scenarios passed; the same `coyote` and `look` assertions failed with the same symptoms. This
shows the acceleration feature is removable without breaking the rest of the starter.

This is an isolated headed consumer matrix, not a claim that the unmodified `pnpm test` chain is
green: that script uses fixed port `4173` and headless browser defaults in this environment.
