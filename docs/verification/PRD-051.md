# PRD-051 verification — native HUD decision

> **Relabelled 2026-08-18 by PRD-155 Phase 2 — this document's native result is not evidence.**
> The `bright=0` native frame below was captured by the runtime's own screenshot path, which until
> `473f9f3` copied the surface mid-frame: after the world pass and before the canvas-layer overlay
> pass. A canvas-texture HUD drawn in that second pass would read as absent while working, which is
> exactly the reading recorded here. The candidate-A harness that produced it no longer exists in
> the tree, so the result **cannot be re-run and is not retracted either** — it is unproven in both
> directions. Any decision resting on "the HUD fails on native" needs a fresh capture before it is
> relied on again. See `docs/verification/prd-155-2026-08-18.md` §2.

**Result:** candidate A failed on Linux desktop; candidate D selected, 2026-08-09.
No framework or template implementation was merged.

## Proof subject

A starter scaffold in `/tmp` used the same `src/render/hud.ts` from both entries. The file
was 40 lines; three lines attached its sprite to the scene camera. It drew `SCORE 1200`, a
72% health bar and a `PAUSED` panel into a 512×256 canvas, then used that canvas as a
Three.js `CanvasTexture`. Seed: 90210; viewport: 1280×720.

Both builds and the source gate passed:

```text
tsc --noEmit:                         exit 0
threenative build --target web:       exit 0, 104 modules
threenative build --target desktop:   exit 0, import-free game.js
desktop execution:                    exit 0, 300 frames in 18,815 ms
```

## Native failure

The executed host logged:

```text
[Canvas2D] Created 1280x720 context
[Canvas2D] JS bindings created
[WebGPU] copyExternalImageToTexture: unsupported source type, width=512, height=256
TN_NATIVE_SMOKE_300_FRAMES:300
```

The native surface is wrong. The source requested a 512×256 offscreen canvas; the host used
the 1280×720 main Canvas2D surface, failed to upload it as a `CanvasTexture`, and did not
render its text. Text metrics and upload performance could not be compared honestly because
functional parity failed first.

## Decision

Candidate A is killed. B and C remain excluded by their layout/DOM ownership cost. Candidate
D is binding: `@threenative/ui` stays web-only, no native HUD abstraction or portable HUD
template ships, and native on-canvas UI remains game-authored Three.js source proved per
platform.
