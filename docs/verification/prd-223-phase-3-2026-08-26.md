# PRD-223 Phase 3 — raytracing handle allocation extraction

**Date:** 2026-08-26

**Host:** Linux x86_64

**Result:** PASS for the host-only allocation contract and the Linux Vulkan backend; other backend
compilation is platform-limited as recorded below.

## Red-green characterization

The new `threenative-rt-handle-allocation-test` was registered before the helper existed. Its object
compiled and its link failed with an undefined `allocateRtHandle` specialization. After the
header-defined template was added, the executable printed:

```text
raytracing handle allocation contract passed
```

The test directly covers all three public handle types. It proves sequential pre-increment IDs,
table insertion, ownership transfer from each input `unique_ptr`, and raw-pointer identity through
both the table and returned handle.

## Negative control

The returned handle was temporarily assigned the already-incremented `nextId`. The executable
exited 1 with:

```text
raytracing handle allocation contract failed: first handle did not receive the pre-increment id
```

Restoring the pre-increment ID made the same target green.

## Extraction proof

The old `nextGeometryId_++`, `nextBLASId_++`, and `nextTLASId_++` allocation tails have zero matches
across the Vulkan, DXR, and Metal backend implementations. `allocateRtHandle` has exactly nine
backend call sites: Geometry, BLAS, and TLAS in each backend. Metal's creation logs remain between
allocation and return.

The generic helper is header-defined because the nine maps contain backend-private resource types.
Putting one definition in `rt_common.cpp` would require platform SDK headers, explicit
platform-specific instantiations, or type erasure. `rt_common.cpp` is unchanged.

## Platform scope

The ordinary host configure initially reported `Vulkan not found - Vulkan RT backend disabled`.
A dedicated Release proof build then supplied SDL's vendored Khronos headers and the system Vulkan
loader explicitly:

```text
[384/387] Building CXX object CMakeFiles/mystral-runtime.dir/src/raytracing/vulkan_rt.cpp.o
[387/387] Linking CXX static library libmystral-runtime.a
raytracing handle allocation contract passed
```

This proves the extracted Vulkan call sites compile on Linux and the shared allocation test runs.
DXR requires Windows, and Metal requires Apple Objective-C++ plus Metal frameworks; neither SDK is
available on this Linux host. Their edits were checked for the same nine-call-site shape but are
**UNVERIFIED**, not reported as compiled or executed.
