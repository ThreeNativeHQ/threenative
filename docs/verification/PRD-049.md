# PRD-049 — physics parity verification

## Phase 0 — host measurement (2026-08-08)

**Result: measurement harness PASS; parity is intentionally not yet a passing claim.** The web
arm is Rapier `0.19.3`; the linked Rust arm is Rapier `0.30.0`. Both read scenario SHA-256
`c5f9c14ec977ee05e00c4662208fb5d8f1707ff5b64cb41b86bfbc6875330b4d` from

This is host evidence only. It is not replay portability, Android evidence, `arm64` evidence,
physical-hardware evidence, or a release-mode performance comparison. The Rust timing below is
from a debug `cargo test` build and exists only to keep the row numeric.

### Proof subject

One seven-body world ran for 180 steps at `0.016666667` seconds per step. Both arms observed all
three scenario coverage controls:

| Control | Web | Rust |
| --- | ---: | ---: |
| character passed upward through the one-way layer | `true` | `true` |
| character reported grounded on moving platform id `2` | `true` | `true` |
| box-only area excluded character id `3` | `true` | `true` |

The same world also contained a fixed floor, a settling dynamic box, autostep and snap-to-ground,
and body id `6` removed while it overlapped area id `5`.

### Commands and collection evidence

```text
pnpm --filter @threenative/runtime-native native:physics:parity
  web:  1 file, 3 tests passed
  Rust: running 1 test; 1 passed
```

The Rust library exposes both `staticlib` (shipping) and `rlib` (integration-test linkage). The
test imports `threenative_native_physics` normally; it does not include or recompile `src/lib.rs`.
`serde`, `serde_json`, and `sha2` are dev-only dependencies required to read the shared JSON and
verify its SHA without duplicating a parser.

The web measurement intentionally does not dispose its scenario world after reading character
collision state. Rapier `0.19.3` otherwise throws `attempted to take ownership of Rust value while
it was borrowed` from `world.free()`. The process exits immediately after writing the artifact;
all recorded simulation observations occur before this cleanup-only limitation.

## Phase 1 — real conformance gate (2026-08-08)

**Checkpoint result: correctly RED on measured D4.** `NativeHostOverWeb` and every delegated
web-over-web simulation assertion were deleted from `native-contract.spec.ts`. A focused census
for `NativeHostOverWeb|createWebPhysicsSimulation` in that file and the physics agent contract
returns zero hits.

The remaining TypeScript contract test proves only facts it can prove without a simulator fake:

- native and web exports resolve to the same four public node classes;
- an unsupported native heightfield throws before the raw host's `createBody` is called.

The linked Rust gate now asserts, in order:

1. scenario SHA and the distinct `0.19.3` / `0.30.0` identities;
2. resting position `≤ 0.02` per axis and character displacement `≤ 0.05` cumulative;
3. exact grounded/collider, area membership, collision-event membership, removal-event count,
   and scenario-coverage results;
4. exact character-state side effects after `setBodyTransform` (D4).

All assertions through item 3 passed. Item 4 produced the required red checkpoint:

Raw Rust rejection strings are still measurements only. They are not asserted as JavaScript
error-class parity; Phase 3 owns that adapter-level proof.

## Phase 2 — observation freshness (2026-08-08)

**Result: freshness PASS; Phase 1's D4 checkpoint remains RED.** `PhysicsSimulation` now states
that character state and area intersections reflect the most recently completed step without a
visible-transform read.

The native adapter owns two independent dirty flags. A successful `createBody`,
`configureCharacter`, `removeBody`, or `step` invalidates both observations. The first subsequent
`readCharacterState` calls only `readCharacterStates`; the first subsequent `areaIntersections`
calls only `readAreaIntersections`. Repeated reads use the cache. `readVisibleTransforms` now does
only its named raw call.

### Required old-behaviour red

The native-adapter test was added before the implementation. After a step and before any visible
read, the old adapter produced:

