## Phase 3 — fail-closed symmetry (2026-08-08)

**Result: adapter validation and teleport-state parity PASS.** The web and native TypeScript
adapters now call the same three exported validators from `simulation.ts` before either backend
sees step input, a visible-transform buffer, or a collision-event buffer. The old inline helper
names and validation messages grep to no second implementation.

`requirePhysicsStepInput` rejects a non-positive or non-finite delta, a non-`Float32Array`
transform input, a negative, fractional, unsafe, or oversized record count, every non-finite
scalar in every declared record, an invalid id, and an unknown id. `requirePhysicsRenderBuffer`
enforces both `Float32Array` and capacity against the adapter's tracked body count.
`requirePhysicsEventBuffer` enforces `Uint32Array` before draining.

The native adapter control uses a raw ABI stub whose methods only record calls; it does not
delegate to a web simulation. Each rejected-input row runs against that adapter and a real Rapier
`0.19.3` web adapter, and asserts constructor identity (`Error === Error`), not message similarity.
A valid unknown `removeBody(999)` is accepted by both adapters. The C++ binding still rejects
missing, non-numeric, non-finite, negative, fractional, or non-exact ids, but ignores the Rust
ABI's `false` result for a valid unknown id.

Rust `set_body_transform` now retains the last completed step's `grounded` and
`ground_collider`. It still performs the existing translation and next-kinematic-translation
writes. This selects the web arm measured in Phase 0 as the contract and closes D4 without
changing the subsequent solver step.

## Phase 4 — collision scan and reusable buffers (2026-08-09)

**Result: D5 retained from measurement; D6 fixed; D7 required no change.** A one-time release
benchmark used fixed boxes spaced four metres apart, zero gravity, 200 warmup steps, and 2,000
timed steps. The temporary ignored test called the shipping `tn_physics_step` ABI and was removed
after capture because this is host timing evidence, not a stable performance gate.

```text
cargo test --release --manifest-path packages/runtime-native/native/physics/Cargo.toml \
  --test parity phase_4_non_overlapping_step_benchmark -- --ignored --exact --nocapture

10 bodies:  total 2,725,252 ns / 2,000 = 1,362 ns/step
100 bodies: total 19,622,294 ns / 2,000 = 9,811 ns/step
300 bodies: total 129,475,075 ns / 2,000 = 64,737 ns/step (0.064737 ms)
```

The 300-body result is 0.39% of the 16.67 ms 60 fps frame ceiling. This does not justify adding
an event-handler implementation, so the measured O(n²) scan remains. It is a host release result;
Android and `arm64` per-frame cost remain open.

The eager quadratic allocations did not survive the kill-switch pass. Buffers now grow linearly
for the normal case and geometrically only after a fail-closed capacity response:

| Bodies | Old event + area allocation | New eager event + area allocation | Reduction |
| ---: | ---: | ---: | ---: |
| 7 | `784 + 392 = 1,176 B` | `256 + 128 = 384 B` | 67.3% |
| 300 | `1,440,000 + 720,000 = 2,160,000 B` | `16,384 + 4,096 = 20,480 B` | 99.1% |

The maximum quadratic size is now only a fail-closed retry ceiling, never an eager allocation.
The web adapter retains drained collision events when a buffer is short, matching the Rust ABI's
existing no-clear-on-short-buffer behavior; a retry therefore cannot lose or duplicate events.
The plugin's 20-overlapping-body negative control required multiple strictly increasing buffer
capacities before one exact drain succeeded. The native area control observed capacities
`[64, 128]`; disabling geometric retry makes that test throw instead of truncating.

The required event-membership revert was observed separately. Temporarily suppressing the web
adapter's drained events made the linked Rust differential fail exit `101` with
`collisionEventSymmetricDifference: 3` and `collision event membership must agree exactly`.
Restoring event delivery returned the gate to 24 web tests plus one linked Rust test, with zero
event-set difference.

Phase 0 measured the overlap-removal stopped-event count as `0` on both arms. D7 is therefore not
a parity bug for the proof subject, and no speculative removal event was added. The exact unordered
collision-event set remains asserted by the linked differential.
