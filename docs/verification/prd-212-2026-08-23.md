      repository's runtime-native and finds every import inside the tarball

### 3. Planted npm-pack-style tarball → specifier census red

`unresolvedTarballSpecifiers` on a manifest carrying `three: "catalog:"` and
`@threenative/core: "workspace:*"` returns two findings naming package, field and specifier
(`fails when a packed manifest still carries a workspace protocol specifier`). `pnpm pack`
substitutes these; `npm pack` does not, and the resulting tarball installs nowhere.

## The false red that shaped the implementation

The first draft matched imports with regexes and reported a third finding:

```
FAIL  @threenative/runtime-native: ... ships scripts/profile-production.mjs, which imports
      './game.js', but scripts/game.js is not in the tarball.
```

`./game.js` is not an import of that script — `profile-production.mjs:646` writes the text
`import game from "./game.js";` into a bundle it generates. The gate now parses with
`es-module-lexer` (added to the catalog at 2.3.1), which reads imports out of source rather than
out of strings and comments. `reads imports out of source rather than out of strings and comments`
pins that behaviour, and `counts a dynamic import that escapes the tarball, and ignores one written
into a string` asserts both halves at once.
