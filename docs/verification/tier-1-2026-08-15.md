### The first diagnosis was wrong, and this is the correction

On 2026-08-15 this lane failed at the first row with
`TN_ANDROID_DISPLAY_ORIENTATION: captured 720x1280 but the lane requires 1280x720`, and that was
recorded here as the AVD's portrait panel — *"the same panel-versus-logical-display hazard
`android-touch.mjs` documents"* — explicitly as a hypothesis, not an answer.

**It was wrong.** `rpg_api36_tablet` has a natively landscape 2560x1600 panel, and it produced the
identical error. The panel was never the cause.

The cause is in the lane itself, and it is two settings fighting:

```console
$ adb shell wm size 1280x720 && adb shell settings put system user_rotation 1
$ adb shell dumpsys display | grep -o 'logicalFrame=Rect([^)]*)'
logicalFrame=Rect(0, 0 - 720, 1280)          # the override, transposed
$ adb exec-out screencap -p | head -c 24 | …
(720, 1280)

$ adb shell settings put system user_rotation 0
$ adb shell dumpsys display | grep -o 'logicalFrame=Rect([^)]*)'
logicalFrame=Rect(0, 0 - 1280, 720)
$ adb exec-out screencap -p | head -c 24 | …
(1280, 720)
```

`wm size` defines the logical display in the panel's **natural** frame, and `user_rotation 1`
rotates it ninety degrees. The lane asked for `1280x720` and then transposed its own request. The
override alone is what makes the display landscape; the rotation only fought it.

`run-conformance.mjs` now sets `user_rotation 0`. One line, and the whole lane goes from
unmeasurable to green.

**The error message was the thing that hid it.** *"The display was still rotating"* names a settle
problem, so both earlier investigations spent their time on settle windows —
`TN_ANDROID_SETTLE_MS=8000`, `TN_ANDROID_ROTATION_TIMEOUT_MS=30000` — and the display had finished
rotating each time, into the wrong shape. A message that had said *"the logical frame is 720x1280;
check user_rotation against the wm size override"* would have cost minutes.
