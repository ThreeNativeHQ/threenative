# Tier 1 — the desktop lane, measured with provenance — 2026-08-15

PRD-076 Phases 1 and 2, desktop half. This is the **third** desktop measurement, and the first
whose numbers can be traced back to the report they came from. It supersedes neither predecessor
by assertion — it reproduces one of them and fails to reproduce the other, and says which.

**It covers the desktop lane only.** The browser lane was not re-run and the Android emulator lane
was not run at all. No mobile-readiness, physical-device or iOS claim is made, and **Tier 1 is not
claimed reached** by this file.

## What this settles, and what it does not

### The r2 desktop summary reproduces exactly

`parity-2026-08-10-r2.md` records `66 / 0 / 1`. This run records `66 / 0 / 1`, with the same single
blocked row. **On the numbers, r2 is right.**

### The r2 desktop exit cell is still impossible, and this run is why it matters

r2 records exit **`0`** for a `66 / 0 / 1` summary. This run produced the same summary and exits
`2`, because that is what the rule computes:

```console
$ pnpm parity:ledger docs/verification/parity-2026-08-10-r2.md
FAIL docs/verification/parity-2026-08-10-r2.md
  Desktop Linux / Exit: records exit 0, but a summary of 66 pass / 0 fail / 1 blocked exits 2.
  The runner cannot emit the recorded value.
```

Phase 0 adjudicated that cell from the code. This is the same verdict from a live run: the summary
was transcribed correctly and the exit code beside it was not. **One hand-typed cell in an
otherwise accurate ledger** — which is the argument for generating them.

### The tier-1 desktop row does not reproduce

`tier-1-2026-08-10.md` records `65 / 1 / 1` with `25-camera-parented-overlay` failing on GPU
validation, *mismatched depth and colour attachment sizes after resize*. That row passes here with
zero GPU validation errors, and it is the resize path that ran:

```console
$ node -e "<read the report>"
overlay: pass | gpuValidationErrors: 0
```

The scene resizes the real renderer per viewport —
`conformance/scenes/shared/camera-parented-overlay.js:55` calls `renderer.setSize` inside the
viewport loop, and the observation comes from the drawing buffer, so removing the resize fails the
row rather than passing it. The failing condition was exercised.

**This does not mean `tier-1-2026-08-10.md` was wrong when it was written.** It means the defect it
recorded does not reproduce at `0358c025`, five days and a great many commits later. The tier-1
report that would settle which no longer exists — that is Phase 0's finding and it has not changed.
Either it was fixed in passing, or it was environment-specific. **This run cannot tell those apart
and does not guess.**

### Therefore PRD-076 Phase 1 has nothing to fix

Phase 1's outcome was *"`25-camera-parented-overlay` passes on desktop after a mid-run viewport
resize, with no scene-side annotation."* That is already true, measured, with the scene file
unedited. `packages/core/src/renderer.ts` and `viewport.ts` are untouched by this PRD: **a fix
authored against a defect that does not reproduce would be a change with no observed red behind
it**, which is the thing this repository refuses everywhere else.

## What was not measured

- **The browser lane was not re-run.** Both predecessors agree on it (`67 / 0 / 0`, exit `0`) and
  nothing here re-checks that agreement.
- **The Android emulator lane was not run.** The two ledgers disagree most sharply there — `67/0/0`
  against `27/40/0` — and that disagreement is **untouched by this file**. Four AVDs exist on this
  host and `adb` lists no running device; booting one, building and installing the app is a
  separate run PRD-076 Phase 2 still owns. The `ANDROID_SDK_ROOT`/`ANDROID_HOME` hypothesis for the
  40-row delta remains untested.
- **The reference-set hash behind either 2026-08-10 run is still unrecoverable.** No report written
  before 2026-08-15 recorded one. This run records `25599d6e…`; the comparison it would enable does
  not exist yet.
- **Tier 1 is not reached and is not claimed.** One lane of three, with one declared exclusion,
  cannot reach it.
