## 2. Merge

`main` and both lanes edit `packages/runtime-native/src/runtime.cpp`. One conflict, both sides
purely additive — PRD-153's measured safe-area insets and PRD-154's platform descriptor — and both
are kept. PRD-154's local handle for the descriptor object is renamed `platform` → `platformInfo`,
because the same scope calls the `platform::` namespace for the insets; qualified lookup would
still resolve, but a local shadowing a namespace in the lines around its own calls is a trap.
`runtime-next-contract.test.mjs` reads that construction by source text, so it follows the rename.

## 3. Two defects the lanes never reached, fixed here

### 3.1 The Android host could not build its own APK — engine bug

PRD-153 pointed `themes.xml` at `@color/tn_boot_splash_background` and declared that colour only
inside `package-android.mjs`, which writes a per-project `values/branding.xml` while packaging and
restores the tree afterwards. The host tree therefore referenced a resource nothing defined:

```text
error: resource color/tn_boot_splash_background not found.
error: failed linking references.
```

`:app:assembleDebug` is step 1 of 4 of the Android device gate, so the gate could not start. The
fix ships `values/branding.xml` with the unbranded defaults `#000000` — the same values
`bootSplashBackground()`/`iconBackground()` produce for a config that declares nothing. The
packaging script already snapshots and restores that path, so a project's own colours still win.

### 3.2 The launch screen outlived the launch — regression, seven templates

PRD-153 moved the loading screen into generated source and changed what it waits for:
`compileAsync(canvasLayer.scene, …)` — four planes, milliseconds — became
`compileAsync(scene, …)`, the whole lit, post-processed world, with a 1-second wall-clock ceiling.

A player never notices. A playtest does nothing but notice: it advances a fixed step as fast as
the machine allows, so an entire scenario runs inside that window while `canvasLayer.opaque` is
still true and the world is not drawn at all. The shooter template failed exactly that way:

```text
TN_CAPTURE_BLANK: after.png: bright pixel ratio 0.04565 is below 0.05   (shooter-fail-condition)
TN_CAPTURE_BLANK: before.png: bright pixel ratio 0.04470 is below 0.05  (survives)
```

The captured frame is the launch screen: 879,398 pixels of one dark colour, plus the 520x10 accent
bar at `anchorY 0.74` — `loading.bar` exactly. Scaffolding the same template from `origin/main`
passes, so it is a regression, and it is a race: instrumenting the run with `console.error` slowed
it enough that the reveal landed in time and the same scenario passed.

The prewarm is worth keeping and the wait is not. `whenReady()` already means the world is safe to
show. `compileAsync` now runs unawaited behind the screen and `whenReady()` is the only gate — no
timer, no ceiling. Applied to all six templates that carry a real loading screen; `minimal`'s is
already a no-op. The two unit tests pinning the old contract are rewritten, not deleted: one proves
the reveal happens with a compile that never settles, one proves a startup that never settles keeps
the screen up through 60 s of fake time.

## 5. The Android emulator red predates this batch

The gate builds, installs and launches the APK, and the app reports
`TN_NATIVE_SMOKE_300_FRAMES:300` with `TN_PRESENTS_TICK:{"frames":60,"presents":60}` — one present
per frame, the invariant PRD-155 added. It then fails on:

```text
FAIL: canvas-layer overlay missing: found 0 pixels of #ff00ff, expected at least 256.
```

Bisected on the same booted emulator, same SDK, same host:

| Tree | Android emulator first proof |
| --- | --- |
| `3677542` (`origin/main`, before PRD-155) | **PASS**, exit 0 |
| `c842a6a` (`main` before this squash, PRD-155 landed) | **FAIL**, same overlay error |
| this squash | **FAIL**, same overlay error |

So the overlay regression arrived with PRD-155's present work, not with PRD-153 or PRD-154, and it
is not an emulator limitation — the same emulator renders the overlay on `3677542`. PRD-155's own
record has the Android lane green on a **Pixel 8**, so whatever this is, it separates emulator from
device. It is left open and unfixed here rather than folded into someone else's squash.

Nothing in this batch is claimed on physical Android or on iOS.
