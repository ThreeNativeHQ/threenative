# PRD-022 verification

Date: 2026-08-06

Status: implementation complete. The viewport lifecycle is accepted. The dedicated
standard-Three browser probe passes; the existing headless WebGPU playtest remains an
explicitly unverified environment result owned by PRD-020.

## What shipped

- `@threenative/core` now owns a `Viewport` lifecycle with readonly size, perspective-camera
  projection updates, resize subscriptions, and disposal.
- `GameImpl` retains the viewport and disposes it with the renderer; a regression test covers
  the observer cleanup path.
- `Ctx.viewport` is available to scenes without moving materials, lighting, shaders, or
  camera framing into the framework.
- The platformer template and Abyss example use the lifecycle for projection and field-layout
  updates.
- A `?viewport` standard-Three probe isolates viewport behavior from the example's WebGPU/TSL
  renderer path.

## Browser proof

Command: `pnpm exec playwright test --config=benchmark.playwright.config.ts`

Result: PASS, 1 test in 2.3s.

The probe resized the Chromium page from 1280×720 to 720×1280, observed matching canvas
dimensions, sampled `camera.main` and `player` through the real playtest bridge, and asserted
that the player remained visible. Page errors and failed requests were both empty.

Result: PASS under the shared headed/Xvfb WebGPU recipe. Movement and camera assertions

## Fail-closed controls

- The focused test uses a fake `ResizeObserver` and proves that disposal suppresses later
  callbacks; no browser behavior is inferred from the unit test.
- The browser test asserts canvas dimensions, player visibility, page errors, and failed
  requests after the resize; an empty or broken probe cannot report success.
- The example remains WebGPU-by-default. The `?viewport` probe is an explicit test fixture,
  not a renderer fallback or a visual framework feature.
