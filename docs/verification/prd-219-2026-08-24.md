Before this lane's change, the Android runner rejected every native `click` before preparation, while `AdbAndroidDriver.setPointers()` already provided the required device-side injection seam through the emulator's rootless `adb emu event send` protocol, including the explicit touch-rotation mapping and coordinate-before-tracking-id ordering proven by PRD-217 Phase 0. The chosen mechanism is a single normalized pointer-down followed by an empty pointer set for pointer-up through that existing driver transport, using the scenario's viewport pixels; because the event enters Android's real window hierarchy, the WebView should receive the touch and apply its `data-tn-interactive` hit-region decision before the UI intent crosses the bridge, rather than using keyboard focus or the game's direct `input.pointer` mailbox method. The final native delivery remains unverified below.
