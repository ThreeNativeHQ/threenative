# PRD-130 Phase 4 — V8 reaches the path a scaffolded user builds through

2026-08-16. [PRD-130](../PRDs/batch-26-08-16/PRD-130-android-default-js-engine.md) Phase 4, the phase
that decides whether the new default reaches anyone but its author.

**Before this, it did not.** `android/prebuilt/` shipped five files — two runtimes, two SDL
libraries, one AAR — and none of them V8. When that directory is populated the Gradle build skips
CMake entirely, so **a project assembled from a release artifact got QuickJS whatever the default
said.** Flipping the engine default without this produces a default only operators with an NDK ever
receive, which is the exact condition PRD-130 exists to remove.

## 1. The runtime binary is engine-qualified, because it genuinely differs

The tempting shape is one runtime plus an optional V8 library. It is wrong: QuickJS is compiled
*into* `libmystral-runtime.so` and V8 is not, so the two builds produce different binaries —
66,618,112 B against 60,416,152 B on arm64. Publishing one runtime for both engines would produce a
process that reports the wrong engine, which is the class of failure `--expect-engine` exists to
catch.

`ANDROID_PREBUILT_V8_ASSETS`, alongside the unchanged QuickJS set:

| Release key | Lands at |
| --- | --- |
| `android-<abi>-runtime-v8` | `jniLibs/<abi>/libmystral-runtime.so` |
| `android-<abi>-v8` | `jniLibs/<abi>/libv8android.so` |
| `android-<abi>-libcxx` | `jniLibs/<abi>/libc++_shared.so` |
| `android-<abi>-v8-snapshot` | `assets/v8/<abi>/snapshot_blob.bin` |

for each of `arm64-v8a` and `x86_64`, plus the shared SDL entries. **The unqualified
`android-<abi>-runtime` keys still mean QuickJS**, so an older consumer of that map is unaffected.

`prepareAndroidPrebuilts({ engine })` selects the set, defaulting to `v8` — the same engine the
source path defaults to, under the same names. Two names for one choice is how a flag gets forgotten.

`copyV8Snapshot` now reads snapshots from `android/prebuilt/assets/v8/<abi>/` when the prebuilt path
is in use and from `third_party/` otherwise: same file, two provenances, one staging path.

## 2. The release lane publishes both engines

`.github/workflows/native-release.yml` builds Android **twice** — QuickJS first, then V8 — and
publishes twelve Android keys instead of five. Publishing only the default would make the documented
rollback unreachable to anyone without an NDK, which is the same defect in the other direction.

**The workflow asserts which engine each runtime links** rather than trusting the filename:

```sh
readelf -d release/threenative-runtime-android-arm64-v8a-v8.so | grep -F NEEDED | grep -F libv8android.so
for quickjs in release/threenative-runtime-android-{arm64-v8a,x86_64}.so; do
  if readelf -d "$quickjs" | grep -F NEEDED | grep -qF libv8android.so; then
    echo "$quickjs links V8; the engine-qualified artifacts are crossed." >&2
    exit 1
  fi
done
```

The two binaries are otherwise indistinguishable by name, and the build order that produces them is
exactly the kind of thing that gets rearranged later.

**The workflow itself is unrun** — no tag was pushed, and this repository has produced zero surviving
releases across ten tags (PRD-078). **But the path it feeds was executed end to end locally**, see §3,
so what remains untested is GitHub Actions, not the consumer path.

**And running it locally caught a bug in the assertion above before any tag could.** The first version
grepped for a literal `v8::`. V8's symbols are **mangled** — `_ZN2v810Uint8Array3NewE…` — so that
matched nothing and would have passed vacuously on *both* binaries, asserting exactly nothing while
looking rigorous. It now reads `DT_NEEDED`:

```
$ readelf -d threenative-runtime-android-arm64-v8a-v8.so | grep NEEDED | grep libv8android.so
 0x0000000000000001 (NEEDED)  Shared library: [libv8android.so]     ✓
$ readelf -d threenative-runtime-android-arm64-v8a.so    | grep -q libv8android.so
                                                          not linked ✓
```

## 3. The consumer path, executed without an NDK

The workflow's twelve artifacts were staged locally under their release names, checksummed into a
`prebuilt-lock.json` by the same code the workflow runs, and served over HTTP. Then the real consumer
path, not a simulation of it:

```sh
$ node -e "prepareAndroidPrebuilts({ engine: 'v8', manifestPath, outputRoot })"
populated packages/runtime-native/android/prebuilt
   assets/v8/{arm64-v8a,x86_64}/snapshot_blob.bin
   jniLibs/{arm64-v8a,x86_64}/{libmystral-runtime,libSDL3,libv8android,libc++_shared}.so
   SDL3-3.2.8.aar
```

Eleven files fetched and **checksum-verified** — the same verification that rejects a tampered
artifact.

Then the build a user without a toolchain performs, with the NDK variables unset and `PATH` reduced
to `/usr/bin:/bin` so CMake cannot be reached at all:

```sh
$ env -u ANDROID_NDK -u CMAKE_ANDROID_NDK -u ANDROID_NDK_HOME PATH=/usr/bin:/bin ./gradlew :app:assembleDebug
BUILD SUCCESSFUL
 60416152  lib/arm64-v8a/libmystral-runtime.so
 29919888  lib/arm64-v8a/libv8android.so
    45420  assets/v8/arm64-v8a/snapshot_blob.bin
    45421  assets/v8/x86_64/snapshot_blob.bin
```

**A V8 APK, built with no NDK.** That is the sentence Phase 4 exists to make true, and before today it
was false.

### And it runs V8 on the phone

The APK above — sha256 `511cc8c0e168a59f…`, 235,594,044 B, assembled with no NDK reachable — installed
on the Pixel 8:

```
4/4 PASS: 300 frames, clean logs, screenshot captured, and process 11565 remained alive for 3000 ms.
jsEngine: V8
```

Engine read from `JS engine created:` in logcat, not inferred from the flag, and the gate would have
exited 1 on any other answer.

**So the whole chain is executed, not argued**: release-named artifacts → checksum-verified fetch →
prebuilt directory → a build with no toolchain → an APK on real hardware reporting V8. That is the
sentence Phase 4 exists to make true, and every link in it ran.

Its libraries are also byte-identical to the source-built APK from Phase 6 —
`libmystral-runtime.so` `75fc190a9eacc211…`, `libv8android.so` `eddea92d4cea2ac3…` — so the two paths
demonstrably deliver the same runtime.

## 4. Negative control — observed red, exit 1

PRD-130 Phase 4's control: populate `android/prebuilt/` from a QuickJS release, request V8, and the
build must refuse rather than produce an APK whose logcat says QuickJS.

```sh
$ ls android/prebuilt          # a QuickJS-shaped directory: 5 files, no V8
jniLibs/{arm64-v8a,x86_64}/{libSDL3.so,libmystral-runtime.so}  SDL3-3.2.8.aar

$ ./gradlew :app:assembleDebug        # no flag, so V8 — the new default
exit 1
Android prebuilt runtime is incomplete for engine 'v8': 5/11 files.
Missing: libv8android.so, libc++_shared.so, snapshot_blob.bin,
         libv8android.so, libc++_shared.so, snapshot_blob.bin.
Populate android/prebuilt/ for this engine, or build with -PthreenativeJsEngine to match what is there.
```

**The refusal names the engine.** "Incomplete" alone sends the reader hunting a corrupted download
when the actual cause is a directory populated for the other engine — the most likely way anyone
lands here.

And the same directory still builds when the engine matches what is in it:

```sh
$ ./gradlew :app:assembleDebug -PthreenativeJsEngine=quickjs
exit 0   BUILD SUCCESSFUL
```

So the check discriminates rather than simply rejecting: it is a contract, not a stricter gate.

**Revert check:** removing the V8 entries from `prebuiltEngineFiles` makes a V8 prebuilt build stop
requiring them, and `distribution.test.mjs` fails on the missing contract.

## 5. What this does not claim

- **No release was produced and no tag was pushed.** Publishing to a public GitHub release is the
  owner's call, not a step to be taken unilaterally. The artifacts in §3 were staged from local builds
  under the exact release names; what a tag adds is *hosting*, not correctness of the path.
- **The GitHub Actions run itself is untested.** The consumer path it feeds was executed end to
  end, including on hardware; what no one has watched is the workflow file running on a runner.
- **Not mobile-ready, not signed.** The release build type still has no `signingConfig` — PRD-128's
  row, inherited rather than solved.
