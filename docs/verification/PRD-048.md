## Phase 3 — prebuilt distribution controls

The installer selects an explicit supported `platform-arch`, requires HTTPS, downloads to
memory, verifies SHA-256 before writing, and fails closed when the platform, manifest,
release entry, fetch, or checksum is invalid. The package allowlist was packed and inspected:
it contains the distribution scripts and exact Android wrapper/project files, but no `src`,
`include`, CMake input, `.cpp`, `.h`, `.cxx`, `.gradle`, or built Android output.

```text
packages/runtime-native/tests/distribution.test.mjs  5 PASS
unsupported aix-ppc64                                rejected with aix-ppc64
corrupted linux-x64 payload                          checksum failure; output absent
packed pnpm consumer + local verified payload        install lifecycle ran; payload installed
pnpm pack --json                                     no C++ runtime source
```

All generated templates explicitly allow the optional runtime lifecycle through pnpm 10's
`onlyBuiltDependencies`; the packed-consumer test proves the hook actually executes. The
real positive gate is still **OPEN**: no published release asset exists, so no checksum lock
was added and no clean machine can build a real target yet. The package contains no dead or
placeholder URL.

condition. The source uses `rapier`, `RigidBody3D`, `Area3D`, and `CollisionShape3D`; bundle

physical Android hardware remain OPEN.
