# PRD-046 verification evidence

Date: 2026-08-08
Status: Web bulk contract and general Android native backend proven; iOS execution, physical
arm64, performance, published assets, and clean-machine consumer distribution remain open

## Phase 0 — Rapier version divergence

The repeatable measurement command passed:

```text
pnpm --filter @threenative/runtime-native native:physics:measure
```

It ran PRD-036's exact contact-rich subject on both arms: seed 1, a five-box stack on a
floor, 300 fixed ticks at 1/60. The web arm used `World.takeSnapshot()` from
`@dimforge/rapier3d-compat` 0.19.3. The native arm used `rapier3d` 0.30.0 and serialized the
same nine fields in the same order as Rapier.js 0.19.3's `SerializableWorld`.

| Measurement | Web 0.19.3 | Native 0.30.0 | Delta |
|---|---:|---:|---:|
| Snapshot length | 9,757 bytes | 9,757 bytes | 0 bytes |
| Byte values | — | — | **62 bytes differ** |
| Maximum final-position delta, five bodies × three axes | — | — | **0** (bit-identical `f32`) |

The final body positions were bit-identical even though 62 serialized solver-state bytes
differed. This is the bounded result PRD-046 required: the version change is not described
as portable replay, and the byte mismatch is not hidden by equal visible positions.

## Phase 1 — web bulk API

The web Rapier backend now exercises the host-neutral shape through
`PhysicsContext.simulation`:

- `step(deltaTime, inputSnapshot)` applies reusable eight-float kinematic records.
- `readVisibleTransforms(renderBuffer)` writes logical body id, position and quaternion
  records into a caller-owned `Float32Array` without per-body API crossings. Backend-specific
  Rapier handles never cross the float buffer.
- The existing plugin, character movement, collision events and scene cleanup remain on the
  same web Rapier world.

Desktop deliberately keeps the existing WASM backend under V8 while Android and iOS select

mobile native uses Rapier 0.30.0. Phase 0 above bounds this version difference; replay is not
portable between the arms.

## Phase 2 — Android native binding and negative controls

The runtime links the Rust static library for both Android ABIs and installs the general
`globalThis.__THREENATIVE_NATIVE__.physics.createSimulation` host. The normal
`@threenative/physics` package entry is selected with the `threenative-native` condition;
the device subject imports `rapier`, `RigidBody3D`, `Area3D`, and `CollisionShape3D` from
that entry. Its import-free bundle was 1,510,618 bytes and contained no Rapier WASM,
Recast marker, or `WebAssembly` marker.

The rebuilt APK passed on `emulator-5554` (x86_64) after 180 fixed 1/60 steps:

| Device scenario | Expected result | Observed |
|---|---|---|
| Normal floor/cube | pass at y=0.5 ±0.02 with collision | **PASS**, y=0.4987237155, distance=0.0012779943, events=1 |
| Wrong expected height (y=1.5) | fail | **FAIL exit 1**, position assertion |
| Upward gravity | fail normal scenario | **FAIL exit 1**, body missed the required floor/collision assertions |
| Excluded collision mask | fall through without collision | **PASS**, y below floor, events=0 |
| Mask scenario against normal APK | fail | **FAIL exit 1**, y=0.4987237155, events=1 |

The post-hardening rebuild also passed after the native binding began rejecting non-number
scalars and wrong typed-array classes. The current normal scenario report is under the
ignored `packages/runtime-native/artifacts/android/physics-normal-post-contract/` directory.
Those generated artifacts are evidence outputs, not tracked release inputs.

This proves the general C ABI, normal public TypeScript adapter, QuickJS host, collision
events, mask behavior and x86_64 simulation plumbing. The release static libraries are
11,399,278 bytes for arm64 and 11,592,018 bytes for x86_64. Arm64 is compile proof only. No
physical arm64 device or performance measurement was available, so neither is claimed.

## Phase 3 — iOS execution

`xcrun`, Xcode, an iOS simulator, and iOS hardware are unavailable on this Linux host.
The root-linked app, simulator verifier, CMake target selection and device driver exist. The
physics builder now selects `aarch64-apple-ios-sim` with `--ios-simulator` and
`aarch64-apple-ios` with `--ios-device`; its Linux `--check` contract and unchanged Android
build both pass. At the time of this local run there was no Apple-target archive produced on
macOS and no iOS physics
execution evidence. Phase 3 therefore remains open; implementation is not execution proof.

## Phase 4 — artifact handoff

CMake accepts an explicit prebuilt artifact through `THREENATIVE_PHYSICS_LIBRARY`, selects
known mobile targets when it is omitted, and fails closed with the missing artifact path and
build command. The native physics libraries live only under ignored `.runtime/` build output;
nothing was added to `third_party/`.

Consumer packaging is owned by the distribution lane. A clean machine with no Rust toolchain
has not yet installed and run the physics artifact, so acceptance criterion 4 remains open.

### PRD-049 Phase 5 repayment annotation — 2026-08-09

PRD-049 deleted the superseded proof-only TypeScript subpath and its Rust/C++/C ABI after its exact
caller census found definitions and generated declaration snapshots, but no non-test consumer. The
general ABI and this document's load-bearing `native:physics:measure` snapshot-byte lane remain.

The deletion removes exactly 207 net native lines: 142 Rust, 24 C header, and 41 net C++ binding
lines. In the concurrently edited worktree, the captured budget moved from 51,778 native LOC before
deletion to 51,563 after it. Of the observed -215, -207 belongs to proof deletion and -8 to unrelated
concurrent native edits. The result remains 1,563 lines above the 50,000 review trigger, so the old
trigger is paid down, **not repaid or closed**. No code was removed or reclassified to manufacture an
under-budget result.
