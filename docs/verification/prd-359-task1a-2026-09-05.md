## Server contract as implemented

`--listen` is required and must resolve; exactly one of `--cert`+`--key` or `--dev-self-signed`;
unknown flags, malformed values and positional arguments exit 2 with usage on stderr. The process
prints `CERT_SHA256 <base64>` and `LISTENING udp=<addr> path=/echo` on stdout and never prints a
private key. SIGTERM and SIGINT close the server against a 5 s bound. `--dev-self-signed` mints a
fresh random ECDSA P-256 certificate valid for 13 days, inside the two-week ceiling
`serverCertificateHashes` requires, with SANs `localhost`, `127.0.0.1`, `::1`.

Origin policy: an absent `Origin` is allowed, the request's own origin is allowed — the native
client sends `https://<authority>` as its own origin, which an allowlist-only check rejects with
HTTP 400 — and any other origin must appear in a `--allow-origin` value, compared after
normalizing scheme, host and explicit-or-default port.

## Deliberately not in this task

`--admin-listen`, `--room`, the `/game` route and the loopback token issuer are accepted by the
PRD's server contract but belong to the tasks that give them meaning; `/echo` is
transport-conformance only. `TN_WEBTRANSPORT_EXECUTABLE`, `TN_WEBTRANSPORT_TEST_URL`,
`TN_WEBTRANSPORT_TEST_CERT` and `TN_WEBTRANSPORT_TEST_KEY`, and the trusted-certificate positive
qualification, are Task 1b's row and its file `tests/runtime-test-utils.ts` was not touched.
