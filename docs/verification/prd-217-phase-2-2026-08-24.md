# PRD-217 Phase 2 — iOS

**Status: written, UNPROVEN. Nothing here has been executed.**

Acceptance criterion 6 asks for iOS to be "either proven or stated unproven. No claim without a
run." This is the statement. `packages/runtime-native/ios/ui_overlay_ios.mm` has never been
compiled, launched, or touched — on a simulator or a device — because this repository has no macOS
host. Every claim in that file's comments is a design intent until a run says otherwise.

## What was written

A transparent `WKWebView` added over the key window, implementing the same contract the Android and
desktop hosts implement:

| | Android | iOS | Desktop |
| --- | --- | --- | --- |
| Assets | `WebViewAssetLoader` | `WKURLSchemeHandler` | `wry` custom protocol |
| Origin | `https://appassets.androidplatform.net/ui/` | `threenative://localhost/` | `threenative://localhost/` |
| Page → host | `addWebMessageListener` | `WKScriptMessageHandler` | `wry` IPC handler |
| Host → page | `JavaScriptReplyProxy` | `evaluateJavaScript` | `evaluate_script` |
| Inbound global | `window.__tnUiReceive` | `window.__tnUiReceive` | `window.__tnUiReceive` |
| Hit test | `dispatchTouchEvent` returns false | `hitTest:withEvent:` returns nil | X11 input shape |

None of those rows is `file://` and none is `pointer-events: none`, on purpose and for the same two
reasons in each column: a real origin is what keeps `fetch` and module imports behaving as they do
on the web build, and CSS hit-testing happens inside a surface the platform has already given the
gesture to.

## What is actually covered

`tests/ui-layer-host-contract.test.mjs` compares the three hosts against the names declared once in
`@threenative/core/ui-layer`, and runs without a Mac. It is the only automated coverage the iOS
host has, and it is worth having: a host that spells one of these names differently has no bridge
at all — silently, because nothing throws when a page posts to an object nobody injected.

```
✓ every host injects the page-facing object under the one declared name
✓ every host calls the one inbound global to reach the page
✓ every host keeps hit regions to itself instead of forwarding them to the game
✓ no host serves the UI from file://
✓ the iOS host states that it is unproven
```

Red-green: renaming `kHostObject` in the iOS host to `@"threenativeHost"` fails the first of those
with the regex and the input named. Restored, 5/5.

`tests/ui-layer-packaging.test.mjs` covers `stageIosUi` — a `web` game with no built UI and a
`native` game carrying one both fail by name at package time, exactly as on the other two targets.
That is the packaging half; the host half is untested by anything but the contract comparison above.

## What a run would have to establish

The rows PRD-217's open question 1 asks of every target, none of which are answered here:

- The web view is genuinely transparent over the Metal layer, and composites for free the way the
  Android measurement showed it does over a GL `SurfaceView`.
- A touch outside the published rectangles reaches the SDL surface, and one inside does not.
- A drag beginning on the game and crossing an island stays with the game.
- An island mid-transition is hit where it is drawn.
- Frame rate with the overlay attached, against the same build without it.

`verify-ios-simulator.mjs` now requires `ios/ui_overlay_ios.mm` to exist, so the file cannot quietly
disappear from the iOS lane; it does not and cannot assert that any of the above is true.
