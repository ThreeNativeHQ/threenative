## Manual jump/fall checkpoint

On a disposable scaffold of the checked-in starter, a headed Brave 150.1.92.143 WebGPU run
sampled the real player transform through the playtest bridge. The scaffold needed the
template's existing `three-mesh-bvh` dependency, supplied from the local cached package for
this temporary probe only; no repository source or dependency manifest changed.

| Probe | Peak Y | Peak tick | Landing tick | End Y | Errors |
|---|---:|---:|---:|---:|---:|
| `JUMP_SPEED = 5` | 1.73354971408844 | 28 | 58 | 0.5098004937171936 | 0 |
| `JUMP_SPEED = 5.5` | 1.996449589729309 | 31 | 64 | 0.5100999474525452 | 0 |

The 0.5 speed edit changed peak height by `0.26289987564086914` and landing by six fixed
ticks (about 0.1 seconds), while the player returned to the same floor height. This proves
the supported consumer can tune jump feel through HMR without losing the live game.
