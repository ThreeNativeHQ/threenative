## What the site is

`site/`, a private workspace member named `threenative-site` — outside `packages/*`, which in this
repository means published npm surface, and deliberately not matching `@threenative/[a-z0-9-]+`,
the pattern `scripts/workspace-packages.ts:9` uses to decide what is publishable. `pnpm budgets`
after the change still reports **10 framework packages, 16 example workspaces**: the site is
counted as neither, which is the whole point of the placement.

## Gates that did not run, and why

- **`pnpm test` end to end stops in its `package-test` phase**, on six `packages/runtime-native`
  bindings tests whose CMake targets have never been built in this worktree. Native compilation is
  opt-in (`pnpm native:build`) and this branch changes nothing under that package. The suite's
  other three phases were run individually and are green; each is in the table above.
- **The site's specs do join the root suite**, through `pnpm -r --if-present run test`
  (`scripts/run-test-suite.sh`'s `package-test` phase), not through root `vitest run`: the root
  `vitest.config.ts` includes only `scripts/**` and `packages/**/__tests__/**`, so `site/__tests__`
  is reached by the workspace fan-out and by nothing else. That is what `site/package.json`'s
  `test` script exists for, and why it builds before it asserts.
- **Lighthouse was not run.** There is no deployed URL yet: the Cloudflare zone, the account id and
  the API token are open questions for the owner (below). The workflow is written and its build job
  is provable; the deploy job has never executed.
- **No visual regression baseline was taken.** The comparison against `REFERENCE.png` was made by
  eye from a 1536×1024 headed-Chromium capture of the built artifact, plus a 390×844 capture. No
  automated pixel gate guards the layout.

## A bug the Playwright lane caught

The mobile drawer rendered and was invisible on every phone width. `SiteHeader` carries
`backdrop-blur`, and `backdrop-filter` makes an element a containing block for `position: fixed`
descendants — so the drawer's `fixed inset-0` resolved against the 68 px header instead of the
viewport and collapsed to zero height. Playwright reported `locator resolved to <div
data-testid="mobile-nav" …> - unexpected value "hidden"`, which is exactly the class of failure a
markup-presence assertion would have passed. The drawer now mounts beside the header in `app.tsx`
and is a native `<dialog>` opened with `showModal()`, so the focus trap and Escape are the
browser's.

## Where the site departs from `REFERENCE.png`, and why

The comp is an approved *visual* target, not a licence and not an API document. Four things in it
are mock-ups, and each is resolved by this PRD's own rules rather than reproduced:

1. **The code sample.** The reference shows `new App({ antialias: true })`. No `App` export exists
   in `@threenative/core`; the portable entry is `defineGame`. The site was corrected to the API.
   Recorded in the PRD's Phase 5.
2. **The hero art.** The photoreal spacecraft render is not ours to ship. The hero and the showcase
   card use original SVG — a planet limb, an atmospheric rim, a deterministic star lattice —
   authored here and recorded in `site/public/og/CREDITS.md`. It carries no raster asset and no
   animation.
3. **The logo wall.** Eight customer logos in the comp; `logos.ts` is empty and `LogoWall` returns
   `null`, so the section does not render. An entry needs a `permission` field naming where written
   permission is recorded.
4. **The play button.** There is no recording, so the showcase card ships without a player and
   links to `docs/architecture/NATIVE-RUNTIME.md` instead.

Two smaller substitutions, both to avoid an affordance that goes nowhere: the header's magnifier is
a real link to GitHub code search for this repository rather than a search box that does not exist,
and `Sign in` is replaced by a `GitHub` link, because Studio has no public entry point. `Solutions`
and `Pricing` render as the reference shows them but are `pending` entries carrying the reason they
do not navigate.

## Design tokens

Sampled from `REFERENCE.png`, dominant colour per region; text colours are the modal glyph pixel
above a luminance floor, because a naive average over a text region reads as background. Three
values in the PRD's planned table were wrong and are corrected there: accent `#e0fb50` (not
`#dffa51`), muted foreground `#c1c3c7` (not `#a6adb4`), border `#202226` (not `#1a1e22`). A fourth
token, `--color-tn-fg-subtle` `#9a9ca1`, was added because the reference uses two distinct greys.
