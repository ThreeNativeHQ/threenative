# PRD-126 Phase 0 — the instrument scores itself, with three raters that had not read round 10 — 2026-08-17

PRD-126 shipped `pnpm visuals:ab` on 2026-08-16 and deliberately did **not** take its own
measurement: the only rater available had already read round 10's score column, reproduced it
exactly, and would have published `mde = 0` for the wrong reason. Phase 0 needed *"three critic
sessions that have not read this one"*. This is that run.

**No visual-quality result is claimed here.** Two template scores moved and they are recorded
below as data from the calibration bundle, not as a round result.

## How it was run

| Item | Value |
| --- | --- |
| Before | the seven template frames as committed at `acabc39` |
| After | the same seven recaptured from the working tree by `pnpm visuals:baseline`, byte-identical to the frames committed at `b7aa467` |
| Bundle | 16 samples: 7 templates × 2 arms, plus 2 injected duplicate pairs, shuffled |
| Raters | three fresh sessions, no shared context, none of which read round 10, this PRD, or any verification file |
| Command | `pnpm visuals:ab --before <before> --after <after> --out <out> --duplicates 2 --raters 3 --verdict ×3` |

**One deviation, and it is a finding.** The bundle's rater prompt is
`docs/product/VISUAL-BASELINE.md`, and that document **publishes round 10's per-template scores** —
*"2 of 7 reach the 4/5 floor, mean 2.86 … `starter` and `action-rpg` are the only two at the
floor; `minimal` scores 2"*. A rater given the real prompt is not blind; the samples are
anonymised but the templates are recognisable from the images. Each rater here got a copy with
that one paragraph redacted. **The bundle should carry a score-free rubric rather than a document
that accumulates results**, and until it does, `promptSha256` records the hash of a prompt that
leaks the answer.

## The measurement

**Minimum detectable effect: 0**, from 6 duplicate-pair observations across 3 raters.

| Rater | `defense` duplicate spread | `action-rpg` duplicate spread |
| --- | --- | --- |
| A | 0 | 0 |
| B | 0 | 0 |
| C | 0 | 0 |

Every rater gave both copies of a byte-identical frame the same score, without exception.

### What that number is, and what it is not

**It is rater determinism on identical input, and for a model rater at this setting it is close to
trivially zero.** A duplicate pair is the *same bytes* carried twice; scoring it consistently
demonstrates that the rater is a function, not that the instrument can resolve a small real
change. Read alone, `mde = 0` licenses treating every ±1 move as a result — which is round 10's
failure with a certificate attached, and §9 of PRD-126 names that outcome as the one to avoid.

**The informative number in this bundle is between-rater, and it is 1.** Raters A and B agree on
all sixteen samples; rater C sits one point below both on every `action-rpg` sample (3 against 4)
and one point below on both `minimal` samples (2 against 3, 1 against 2).

| Template | A | B | C | Between-rater spread |
| --- | --- | --- | --- | --- |
| action-rpg (both arms) | 4 | 4 | 3 | **1** |
| minimal::after | 3 | 3 | 2 | **1** |
| minimal::before | 2 | 2 | 1 | **1** |
| starter::after | 2 | 1 | 2 | **1** |
| platformer, racing, shooter, defense | identical across raters | | | 0 |

The three-rater median absorbs this — which is what a median is for — but a round scored by **one**
rater is exposed to it in full. That is round 10's ±1, reproduced here by independent means.

## Phase 0's pre-committed branch

PRD-126 §Phase 0 committed to two outcomes in advance:

> - **Spread ≥ 1.** The round-10 reading is confirmed … Proceed.
> - **Spread < 1 under pairing alone.** Then the pairing fix in `visual-ab.ts` was sufficient on
>   its own, the three-rater median is unnecessary cost … **Say so and cut the scope.**

**The duplicate-pair spread is 0, so the second branch fires on the letter of the rule — and the
between-rater spread is 1, which is the first branch's condition measured a different way.** Both
are reported rather than one being chosen, because the rule was written expecting a single number
and this bundle produced two that disagree about what they are measuring.

**Recommendation, for the owner rather than taken here:** keep ±1 as the working resolution for any
round scored by a single rater, and use `mde = 0` only for a comparison run through a paired
bundle with three raters, as this one was. Cutting the three-rater median on the strength of a
duplicate-pair zero would remove the only mechanism that caught rater C's offset.

## The deltas this bundle happened to produce

Recorded because they were measured, and flagged because this run exists to calibrate the
instrument, not to score the templates.

| Template | Before (`acabc39`) | After (working tree) | Δ | Verdict at mde 0 |
| --- | --- | --- | --- | --- |
| starter | 4 | 2 | **−2** | LOSS |
| minimal | 2 | 3 | +1 | WIN |
| action-rpg, defense, platformer, racing, shooter | — | — | 0 | INDETERMINATE |

`starter` losing two points survives any resolution this instrument might have, and all three
raters put its after-frame at 1–2 against a before-frame all three scored 4. **It is worth a look
before the next round** — round 10 recorded reverting a landmark change that cost `starter`
exactly two points, and the current tree's frame still scores where the reverted one did.
No cause is claimed here; nothing in this run touched a template.

## What this does not claim

A model instrument, not the human blind session `docs/product/VISUAL-BASELINE.md` requires. One
still per template, no motion, no interaction — a template that reads well in a frame and plays
badly scores well here, which two rounds have now recorded as a known property. Three model raters
drawn from the same family are not three independent judgements in the sense a human panel would
be, and their agreement should not be read as convergence on truth.
