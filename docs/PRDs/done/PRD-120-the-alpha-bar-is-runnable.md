## 1. Why a table is not a gate

The beta bar in `docs/strategy/ROADMAP.md:30-36` is six markdown rows with ✅ and ⚠️ typed into
them by whoever last edited the file. Its row 4 has read *"Tier 1 not reached"* since 2026-08-10.
Nothing recomputes it, so nothing can contradict it, and nothing notices when a row becomes true.

This repository already knows what the alternative looks like and uses it everywhere else:

| Instrument | What it does | Convention it establishes |
|---|---|---|
| `scripts/check-budgets.ts` | `pnpm budgets` — hard invariants fail, LOC triggers report | a gate that fails, and a number that is reported but never silenced |
| `scripts/round-next.ts` | `pnpm round:next` — computes the single next action from the ledger | the state of the loop is derived, never asserted |
| `scripts/studio-probe.ts` | `pnpm studio:probe` — one line per check, exit 0/1/2 | `2` means *never reached the check*, distinct from `1` = failed |

The alpha bar gets the same treatment: `pnpm alpha:bar`, one line per row, exit `0` alpha,
`1` a row is red, `2` a row could not be measured.

**`2` is the important exit code.** The failure this repository has been burned by is a check that
reports green while asserting nothing — a broken archive, a dropped assertion, a renamed ledger
column. A row whose evidence file is absent prints `unmeasured` and exits `2`. It never prints a
pass.

## 2. The instrument defect this PRD also fixes

`scripts/round-next.ts:78-82`:

```ts
const directory = path.join(repo, "docs", "PRDs");
const fileName = fs
  .readdirSync(directory)
  .find((file) => file === `${prd}.md` || (file.startsWith(`${prd}-`) && file.endsWith(".md")));
if (fileName === undefined) return false;
```

`readdirSync` does not recurse. **Any PRD inside a batch folder reads as "not open" to
`round:next`**, which then treats a blocking PRD as resolved. That is true today for every PRD in
`starter-kits/`, `asset-pipeline/`, `studio-hosting/`, `production-readiness-26-08-14/` and now
`alpha-readiness/` — including PRD-113 and PRD-114, which the round-6 ledger names as blockers.
This is a code read, not a run; Phase 0 reproduces it before Phase 1 changes a line.

Same class of defect as the round-5 column rename that silently disabled `round:next`: a
documentation move breaking a measurement instrument, with no gate reporting it.

## 4. Reachability

**Entry point:** a human or agent runs `pnpm alpha:bar`. There is no server, no UI, no cron.

**Full flow:** run the command → each row executes its own evidence check (a file read, a registry
query, a script invocation) → each row prints `pass` / `fail` / `unmeasured` with the exact
evidence it read → the exit code is the worst row → the batch README table is regenerated from
`--json`.

**What does this replace?** The typed ✅/⚠️ table. It is removed by being generated: the README
section between the generator's markers is overwritten, and a hand edit is reverted on the next
run — the same contract `pnpm sync:agents` and `scripts/count-loc.ts` already use.

## 6. Acceptance criteria — consumer-scoped

1. `pnpm alpha:bar` on today's tree exits **1 or 2**, prints at least one red row, and names the
   file or command that made it red. A run that exits `0` today is a bug in the bar, not an alpha.
2. Deleting the evidence file behind any row makes that row print `unmeasured` and the command
   exit `2` — never `pass`, never `0`.
3. The table in this batch's `README.md` is byte-identical to the generator's output; hand-editing
   a cell and re-running the generator reverts it.
4. `pnpm round:next` reports a PRD inside a batch folder as open, proved by a spec case that fails
   at the previous commit.
5. Someone who has never read this batch can run one command and get the same answer to *"are we
   at alpha?"* that a reader would get from the whole folder.

Rejected wordings: *"the script runs"*, *"seven rows are implemented"*, *"the table matches the
PRD statuses"* — the last is satisfiable by reading the same hand-typed statuses the bar exists to
replace.
