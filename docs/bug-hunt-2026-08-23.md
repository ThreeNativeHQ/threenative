## Verified defect

### Native `decodeAudioData` is not a Promise and is not chainable — FIXED

- Layer: engine/native runtime.
- Location: [audio_bindings.cpp:529](/home/joao/projects/threenative/threenative-engine/packages/runtime-native/src/audio/audio_bindings.cpp:529)
  through [audio_bindings.cpp:547](/home/joao/projects/threenative/threenative-engine/packages/runtime-native/src/audio/audio_bindings.cpp:547).
- Contract: the documented native Web Audio surface requires `decodeAudioData` to return a Promise,
  support legacy callbacks, and reject invalid input; see `docs/PRDs/BLOCKED/review-cap/PRD-057-native-audio-parity.md:174-175`.
- Cause: the implementation creates `engine->newObject()`, installs ad-hoc `then`/`catch` methods,
  and returns `newUndefined()` from those methods. It returns the plain object at line 547.
- Impact: `instanceof Promise` fails, and `decodeAudioData(...).then(...).then(...)` fails because
  the first `then()` returns `undefined`. `await` may assimilate the object, but that does not make
  the browser Promise contract complete.

RED against the current source shape:

```text
source proof: custom thenable at bytes 23768-24882
RED observed: decodeAudioData did not return a native Promise
red_exit=1
```

The probe asserted the current source contains the custom `newObject()`/`return thenable` path, then
modeled its observable return value and required a native, chainable Promise.

GREEN after the minimal correction model (`Promise.resolve(settled)`):

```text
GREEN observed: Promise return and chainability contract pass
green_exit=0
```

#### Native runtime execution (the follow-up)

`packages/runtime-native/tests/audio_decode_promise_test.cpp` creates the runtime's own JavaScript
engine, installs the real audio bindings, and drives `decodeAudioData` from JavaScript the way a
game does — no window, no GPU, SDL on its dummy audio driver. It builds a one-frame WAV inline so
the proof needs no asset on disk.

RED against the shipped thenable:

```text

then() on the failure path returns a chainable Promise: then() returned [object Undefined]
```

The two legacy-callback assertions passed in the same red run, so the fix had to keep them passing.

GREEN after the binding settles a real Promise from the engine's own `Promise` constructor
(`Promise.resolve(buffer)` / `Promise.reject(new Error(message))`), with the legacy `onSuccess` /
`onError` callbacks still fired first:

```text
engine: V8
[Audio] Decoded audio: 1 frames, 1 channels, 44100 Hz
[Audio] decodeAudioData received an empty or non-ArrayBuffer argument.
native decodeAudioData Promise contract passed
green_exit=0
```

Executed on Linux desktop against V8 13.1.201.22, the platform default for that build. QuickJS and
JSC were not executed: this build compiles in V8 only (`MYSTRAL_JS_V8`), and iOS/Android engines
need their own lanes. The binding reads `Promise` off the global rather than assuming an engine
API, so it carries, but that is reasoning, not a result.

The proof runs headlessly by design, so it is wired ahead of the display-dependent desktop gates:
`node scripts/verify-desktop-audio.mjs`, and first in `pnpm native:verify:desktop`.
`packages/runtime-native/tests/audio-decode-promise.test.mjs` keeps the shape and that wiring in
the default `pnpm test` gate; all five of its assertions are red against the pre-fix source.

A decode failure now rejects with an `Error` rather than a bare string, which is also what the
legacy `onError` callback receives — the same value on both call styles, as a browser does it.

### Native physics calls reach a disposed world

- Layer: engine/native physics seam.
- Location: [host.ts:379](/home/joao/projects/threenative/threenative-engine/packages/physics/src/native/host.ts:379)
  through [host.ts:535](/home/joao/projects/threenative/threenative-engine/packages/physics/src/native/host.ts:535).
- Contract: after `dispose()`, both physics backends must reject post-dispose surfaces instead of
  touching freed backend state. The web adapter already called `requireLive()` on these paths; the
  native adapter omitted it for `step`, transforms, queries, observations, and event draining.
- Impact: native teardown could call into a freed C++ world, while the web backend threw the shared
  `Physics simulation is disposed.` error.

GREEN after adding `requireLive()` to every omitted native surface:

```text
PASS packages/physics/__tests__/dispose-contract.spec.ts (2 tests)

```

The red test and source fix landed together in commit `94b088f`:
