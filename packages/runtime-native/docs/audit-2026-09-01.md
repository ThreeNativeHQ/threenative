Read-only pass over `packages/runtime-native/src` (49.7k lines C++/ObjC++, 123 files), CMakeLists (101 KB),

## Tier 1 — quick wins (under an hour each, mechanical, low risk)

### 1. Dead source compiled into every binary
- `src/input/input_shim.cpp` (147 lines): every function body is a `// TODO`. Only reference anywhere is a
  comment in `runtime.cpp:1328`. Compiled (listed in CMakeLists), called by nobody.
- `src/canvas/canvas.cpp` (64 lines): six TODOs, zero implementation.
- `src/platform/surface_linux.cpp` / `surface_win32.cpp`: `createX11Surface` / `createWaylandSurface` return
  `nullptr` after printing a log line. No caller — grep for `createVulkanSurface|X11Surface` finds none.
- `src/gltf/gltf_loader.cpp` (475 lines) + `include/mystral/gltf/gltf_loader.h` + `src/utils/cgltf_impl.cpp`:
  **not in CMakeLists at all** and not included by anything. The live glTF path is JS
  (`tests/gltf-loader-fixtures.test.mjs` drives `conformance/scenes/shared/gltf-loader-*.js`).
  ~700 lines of dead C++ that reads as if native glTF loading exists.
- Effort: delete + one CMake edit. Impact: removes four false capability signals for a cold agent reading the tree.

### 2. `localStorage.setItem` does a full disk round-trip per call
`src/storage/local_storage.cpp:337-352`. Every `setItem` / `removeItem` / `clear` calls `flush()`, which
re-serializes the **entire** store to JSON, opens a temp file, writes, and `rename()`s. A game that saves
progress in a loop or per frame pays N serializations + 2 syscalls each, synchronously on the game thread.
Web `localStorage` is memory-speed; this is not a portable-behaviour match.
- Fix: dirty flag, flush at frame end / on `pollEvents` idle / at shutdown. Keep the atomic rename.
- Also: no `fsync` before `rename`, so the "atomic write" is not crash-durable, and the fallback path on
  rename failure writes non-atomically over the real file.

### 3. Per-frame heap churn in the frame-op replay hot path
`src/webgpu/bindings_frame_stream.cpp:52-58` constructs **six `std::unordered_map`s per frame**
(encoders, renderPasses, renderOwners, computePasses, computeOwners, commandBuffers) — allocate, fill, destroy,
every frame, forever. Ids are small and dense.
- Fix: hoist them onto `BindingsState` and `.clear()` each frame (keeps buckets), or use flat vectors indexed by id.
- Same file, per-op allocations with no `reserve`: `std::vector<uint32_t> values(n)` per `setBindGroup`
  (lines 227, 288 — one malloc per bind-group set per draw), `bundles.push_back` (line 249),
  `rawBuffers.push_back` (line 316), `colors(count)` per `beginRenderPass` (line 143).
  Dynamic-offset counts are ~0-4 in practice; a small stack buffer removes the malloc entirely.
- Impact: this is the exact path `TN_HOST_GAP`'s `frameReplay` segment measures.

### 4. Stale local disk: ~14 GB
`build/` 8.5 GB across 10 build trees, `artifacts/` 5.7 GB (dated dirs back to 2026-08-27), `.runtime/` 940 MB,
`third_party/` 1.2 GB. All gitignored, none tracked — pure local reclaim. Do not touch `third_party/`
(the download cache; see the never-symlink rule).

## Tier 2 — real bugs, half a day each

### 5. Malformed frame stream calls wgpu with null handles instead of failing closed
`bindings_frame_stream.cpp`. The lookup lambdas (`renderPass`, `buffer`, `encoder`, `computePass`, `texture`,
`viewFor`) call `fail()` and return `nullptr` — but `fail()` only sets `r.ok = false`; **the current record keeps
executing**. So an unknown id lands as:

    case 17: auto p = renderPass(r.u32());   // p == nullptr, fail() already called
             wgpuRenderPassEncoderEnd(p);    // null deref inside wgpu-native

29 unguarded sites: 12 × `renderPass(r.u32())`, 8 × `buffer(...)`, 6 × `encoder(...)`, 3 × `computePass(...)`.
Case 34 (`resolveQuerySet`) is the only one that guards (`if(!r.ok||!e||!q||!dst) break;`) — the author knew.
This violates the fail-closed rule: malformed input must throw, not crash the process.
- **Test gap matching the bug exactly**: `tests/frame_op_stream_replay_test.cpp:229-243` covers truncated header,
  bad magic, unaligned record, unknown opcode, and unknown *buffer* id — and opcode 1 (writeBuffer) is the one
  case that validates its id before use. No case reaches the unguarded handles.
- Fix: `if (!r.ok) break;` after each lookup, or make the lambdas set a flag the switch checks once.

### 6. Unbounded allocation from stream-declared counts
Same file. `count` in `beginRenderPass` (line 143, `std::vector<...> colors(count)`) is read straight from the
stream and used to size a vector **before any validation** — the record-length check bounds `recordBytes`, not
`count`. A `count` of 0xFFFFFFFF is a ~300 GB allocation → `bad_alloc` → abort. Same shape for `n` in
`setBindGroup` (227/288) and `executeBundles` (245). Case 31 does validate its payload against the record;
these do not.
- Fix: bound each count by the bytes remaining in the record before allocating.

### 7. Device-feature requests are copy-pasted 9 ways and have drifted
`src/webgpu/context.cpp` builds `requiredFeatures` in **three functions** × three backend branches
(`initializeHeadless` ~L449, `createSurface` ~L829, `createSurfaceWithDisplay` ~L1127). Confirmed divergences:

| Divergence | Where | Consequence |
|---|---|---|
| `maxColorAttachmentBytesPerSample` bump missing | `initializeHeadless` only | MRT/deferred scenes validate windowed and fail **headless** — the playtest/conformance lane |
| No compression features requested at all | `createSurfaceWithDisplay` + wgpu branch (L1220-1234) | KTX2 `detectSupport` reports nothing on Linux X11/Wayland with wgpu-native; the BC7 pipeline output is unusable there |
| `CoreFeaturesAndLimits` not requested | wgpu branch at L449 and L1127 (present at L829) | the file's own comment: "one that forgets silently loses MSAA and the GPU meter" |
| `RG11B10UfloatRenderable` requested on Dawn only | all three wgpu branches | three.js SSGI target is rg11b10ufloat + RENDER_ATTACHMENT with no fallback → device lost on wgpu |
| `hasIndirectFirstInstance_ = true` set without pushing the feature | L1222-1225 | JS believes `firstInstance` works; the device never requested it |
| Magic `featureCount < 2` against a `[6]` array | L1233 | caps the list for no stated reason |

Linux desktop defaults to Dawn (`build/tn-linux/CMakeCache.txt`: `MYSTRAL_USE_DAWN=ON`), so rows 2-4 bite the
wgpu builds (`tn-linux-dual`, iOS) rather than the default lane — but the headless row bites everyone.
- Fix: one `buildRequiredFeatures(adapter, backend)` helper, three call sites. This is exactly the
  "package lists drift when hand-maintained" pattern already in memory, in C++.

### 8. `HostGapMeter` period stats and segment stats come from different sample sets
`src/runtime.cpp:270-283`. On a hitch, `closeFrame()` drops the frame's segment sample **and clears the whole
`periodMicros_` vector**, but leaves the ~299 already-collected `samples_` in place. The emitted
`TN_HOST_GAP` line then reports `frames: 300` with a `periodP50Ms` computed from however few periods survived
after the last hitch. A hitch at frame 299 gives a p50 over one sample, printed next to a 300-frame segment
breakdown. Any comparison across runs built on `periodP50Ms` is reading a sample size it does not print.
- Fix: drop the matching period entry only, or track `periodMicros_` per-sample so the two stay aligned.

### 9. `renderOwners[id]` inserts on lookup
`bindings_frame_stream.cpp:266`: `if (renderOwners[id] == state->presentation.surfaceRenderEncoder)` uses
`operator[]`, which default-inserts a null entry for an unknown id before comparing — and a null
`surfaceRenderEncoder` would then compare equal, wrongly marking the surface pass ended. Use `find`.

## Tier 3 — larger, worth scheduling

### 10. `clearFrameHandles` is O(all live handles) every frame
`src/js/v8_engine.cpp:1255`. `frameHandles_` holds **both** per-frame and protected (long-lived) handles;
the per-frame sweep walks the entire set and does a second hash lookup in `protectedHandles_` for each entry,
skipping the protected ones — every frame, forever. A game holding thousands of protected handles (callbacks,
materials, buffers) pays that scan at 60 Hz for handles that can never be freed.
- Fix: keep protected handles in their own container; `freezeHandle` moves out of `frameHandles_`,
  `freeHandle`/`unprotect` moves back or releases directly. Then the sweep is O(this frame's handles).
- Bonus: `frameHandles_` could be a vector once protected handles are out of it (insert + bulk-clear only).

### 11. Every bridge value allocates a pooled `v8::Persistent` + a hash-set insert
Same file, 38 `frameHandles_.insert(...)` sites — `newNumber`, `newString`, `getProperty`, every return value.
The packed frame stream exists precisely to avoid this for render commands; everything else (input events, timers,
property reads, physics) still pays it. A generation-stamped slab (index + generation instead of a raw pointer in
a hash set) would cut the per-crossing cost measurably. Measure with `TN_JS_CPU_PROFILE` before committing.

### 12. `getCurrentTexture().createView()` allocates a registry entry per frame, freed only by GC
`src/webgpu/wrapper_factories.cpp:38-52`. Each call creates a `WGPUTextureView`, a JS wrapper, and a registry
entry, released through `registerRelease` on a V8 weak callback. Live native view count is therefore bounded by
GC cadence, not by frame count. Worth an explicit meter (peak `textureViewRegistry.size()`) before it becomes a
device-memory report from a user.

### 13. CMakeLists.txt is 101,933 bytes in one file
Every source list, every backend probe, every target hand-enumerated. Two files already fell out of it
(`gltf_loader.cpp`, `cgltf_impl.cpp` — item 1) with no error, because nothing cross-checks the tree against the
list. A `scripts/` check ("every .cpp under src/ is either listed or explicitly excluded") is a small guard that
would have caught the drift; splitting into `cmake/*.cmake` per subsystem is the larger version.

## Notes on things that looked wrong and are not
- `paceToPresentationCap` (`bindings_presentation.cpp`) is a correct drift-compensating `sleep_until`, not a spin.
- The blocking post-present `wgpuDevicePoll(device, true, …)` is behind `TN_WEBGPU_GPU_DRAIN_PROFILE`, off by default.
- The per-frame screenshot mailbox poll (`runtime.cpp:934`) already caches its path; it is one `getenv` + one `stat`.
- Registries are reclaimed via `registerRelease` GC hooks, not leaked outright.
